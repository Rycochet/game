# server

The authoritative game simulation. Native only, never in the browser. Clients connect over WebSockets (`network`, which also serves the web client's files on the same port, over TLS unless behind a proxy), or in-process for single player. It runs worlds (each from its secret `WorldSeed`), as many at once as its players are in, and answers clients through `shared::protocol` messages: welcoming them, sending the world map chunks (pois) coming into each player's sight, and running their visits to sites (entering, stairs, leaving) while sending each level's cells as they come into sight. It checks every step a player takes (`shared::movement`) and tells the client where it has them. It saves the world, the sites entered and each character (what they know, where they are) in its own data folder, so a player continues where they left off. Mobs stand on the levels in use, and players are told who is in their sight.

If `upnp` is on (or `HOW_UPNP`, `upnp_from_environment` in `environment.rs`, which wins), opening starts `network/upnp.rs`'s `RouterWork` (its own "upnp" thread and small tokio runtime, through `igd-next`): `start(external, local)`: finds the router (10 s), never for a loopback listen address, forwards TCP to this computer's address on the router's network (`lan_address`: the one listened on, or the route to the router) for an hour, renewed every 30 minutes (or for good if the router only allows that), asks the external address (`is_shared` flags private and CGNAT ones), and removes the forwarding when dropped (closing, new settings, stopping); `tell_router_news` sends the host `Online` again with each `RouterPort`, after `Opening` at first (`Off` when turned off). Tests never ask a real router. While open, `ServerOptions` has `online` and `guests` on, `idle_minutes` at `IDLE_MINUTES` and `pausable` off (a paused clock resumes, telling the host), and the host is told `Online(OnlineState)`.
- `crates/server/src/latency.rs`: `Pings` (numbers a client can't guess for WebSocket pings, and times the answers), `Latency` (average round trip and how much it varies; `measured`, `no_answer` say when a connection goes into or out of trouble). Tests: timing, made-up answers ignored, trouble reported once each way.
- `crates/server/src/debug_api/`: the debug API (`DebugApiPlugin`, `AddDebugMethod`, the `server.` methods in `methods.rs`), most of it only with the `debug-api` feature: see `docs/context/debug-api.md`. `ServerPlugin` adds the server's methods; `main.rs` adds the plugin after the log plugin, `start_embedded` with port offset 1 (the client has the usual port).
- `crates/server/src/embedded.rs`: `start_embedded(WorldSeed, data, Difficulties) -> (ClientLink, EmbeddedServer)`: single player (the difficulties from Server Options, unless `HOW_DIFFICULTIES` sets them) (with `OnlinePlugin`, so its player, the `Client::host`, may open it to others), one character made on first run and saved like an account's, stops when its client has gone. `EmbeddedServer`: dropping it waits for the thread (drop the link first). Test: welcomes its client, and saves when it leaves.
- `crates/server/src/main.rs`: the standalone binary `hall-of-worlds-server`; `--health` only runs `check_health` on `HOW_ADDRESS` and exits 0 or 1 (Docker's `HEALTHCHECK`). Otherwise `headless_app` (saving in `default_data_folder()`) plus `log_plugin()` and `NetworkPlugin`. Environment: `HOW_ADDRESS` (the plain port, default `0.0.0.0:24690`), `HOW_TLS_ADDRESS` (the secure port, default `0.0.0.0:24691`), `HOW_BEHIND_PROXY=true` (everything on the plain port too; any certificate still works on the secure one), `HOW_DISABLE_SSL=true` (no secure port or certificate; needs the proxy option, and refuses a certificate it would ignore), `HOW_TLS_CERTIFICATE` + `HOW_TLS_KEY` (your own PEM files, both or neither), `HOW_TLS_NAMES` (more names and addresses for a generated certificate, comma separated), `HOW_LETS_ENCRYPT_DOMAIN` (ask Let's Encrypt, accepting its terms; the domain's public port 443 must reach the secure port; a clash with own files stops the server), `HOW_LETS_ENCRYPT_EMAIL` (optional), `HOW_DEBUG_LETS_ENCRYPT_STAGING=true` (its test service), `HOW_WEB` (the web client's folder, e.g. `dist`; its history goes in the data folder's `web-history`), `HOW_DATA`, `HOW_GUESTS=false` (no guests, which stops the server from starting until there is another way in; on by default), `HOW_DEBUG_TOOLS=true` (accept dev tools messages from anyone connected, for private test servers; off otherwise, and clients are told in `Welcome`), `HOW_SERVER_NAME`, `HOW_PLAYER_LIMIT` (0 for none), `HOW_IDLE_MINUTES` (default `IDLE_MINUTES`, 15; 0 for never), `HOW_DIFFICULTIES` (names separated by commas; all if blank or unset; logged on starting), `LOG_LEVEL=debug` (also logs every connection's every round trip, a line a second for each client, for looking into network trouble; trouble and each connection's summary are always logged).

## Notes

- Embedded, the server runs on its own thread ("server") as its own Bevy `App`, so it shares no components or resources with the client: everything goes through the `Link`. The `App` is built on that thread (it can't move between threads). It adds no log plugin (the client's is used; only one can exist per process). When the client hangs up (on quitting) it saves and stops, and the client waits for it; if the process is killed, at most `SAVE_EVERY` of play is lost.
- Saves from before `shared::site::FORGET_BEFORE` are ignored when loaded and saved over: characters start again, sites are made new at the current versions. `world.ron` stays, as the world comes from its seed.
- For now every poi is sent to everyone (`world_map::ALL_POIS_KNOWN`, the owner's choice: a TODO until characters can learn of them). With it off, pois are hidden until known (`world_map::known_poi`): towns are seen by all, the rest only with `KnownPoi::known` or `visited`, or after `DevRevealPois` (this connection only). Nothing sets `known` yet. Entering (`enter_poi`) checks the same thing, as a client could otherwise enter one it was never told of.
- What a character knows (world map chunks seen, with or without a poi: all sent again on connecting, for the player's map; cells of each level seen) and where they are is saved; what the client has been sent is per connection. A site's generator version is fixed when it is first entered (one per site, not per level: a site's levels must agree on their stairs). `changes` are applied but nothing makes any yet; `last_visit` is recorded for resets, which come with spawns. Dev tools sites are saved too (`SiteId::Dev`); Dev Areas only while in use (`SiteId::DevArea`, forgotten on leaving). Mobs on a Dev Area come from `DevArea::spawns`, not `mob::spawns` (`entities/population.rs`).
- Tests that need saving use `TestFolder`; everything else uses `ServerWorld::new` (nothing saved). Runs for checking visuals should set `HOW_DATA` to a scratch folder, so they don't move the owner's character.
- Movement is steps only (`ClientMessage::Step`): the server never takes a position from a client. Steps, and entering and leaving, wait in `Client::waiting` until the character has the energy (`connections::act`, each tick after their messages), up to `MOST_WAITING`, past which steps are dropped and `Position` puts the client right. One `UseAbility` waits there at a time; `WithdrawAbility` takes it out again (the player moved or chose another). Network jitter only delays them. Energy isn't saved: a character joins ready to act. On the world map, water stops steps, and the server's clock and the moons set the tide.
- Only one on a cell: mobs never step where another mob or a player is (`run_mobs`'s `Taken`), a player's step onto a mob swaps them unless it is an enemy, which refuses it (`enemy_at`, `swap_mob`), and one on a cell someone arrives on otherwise moves aside (`move_mob_aside`). Players can share cells with each other.
- Secret doors are sent as walls, unless `Client::truesight` (`level_chunks`); changing it sends a level with any again (`sites::truesight_changed`).
- Items' secrets (`shared::item`): everything sent about items goes through `Client::send_inventory` or `Client::as_seen`, which hide what hasn't been found out unless `Client::truesight` (from `DevTruesight`; per connection, not saved). Saves keep the truth. The player's own removals ask `Client::may_take_off` first: moving, binning, giving and dropping. It refuses a curse, marking it found out, but not in god mode, and lets through what is covered for the usual refusal, which reveals nothing.
- Territorial mobs (by `Temper`): one that sees a stranger guards (`Doing::Guarding`), standing between them and its home at its territory's edge, or nearer if they are, and stays neutral. Anyone not friendly it sees inside its territory is remembered as trespassing (`Event::Trespassed`), which turns it unfriendly for a while: it then attacks, but only while they are within `LEASH` of its home, and guards again beyond. The leash is from home, not the mob, as someone no faster could never get further from it. Swapping places with a guard is allowed, and puts the player inside, so it counts as a trespass.
- Scent (owner, 2026-11-05): everything that walks on a level leaves a mark on each cell it steps off (who, which way, the action tick, how strong: `shared::mob::scent_strength`), players by their position changing between ticks (`Population::last_at`), mobs after acting; taking stairs marks the stairs with where they lead (`saw_stairs_taken`). Nobody in god mode leaves any. Each creature keeps only its latest mark per cell; `run_mobs` sweeps marks past `SCENT_KEPT_FOR` every 10 s. A chasing mob that loses someone where it last saw them starts `Tracking` if its kind can smell: it goes the way their mark on its cell says, or to the freshest mark beside it newer than the last it followed (so never back), back to `Going` on seeing them, `Following` at stairs if its kind uses them, and settles when the trail is gone or too old for its nose. Marks are saved with the level (`LevelSave::scents`, swept on loading) whenever they have changed at a save, so active levels' saves change with every step; marks left after the last save of a level that is let go are lost.
- God mode (`Client::god_mode`, from `DevGodMode`; per connection, not saved): left out of `run_mobs`' `spots`, so no mob notices them and one already after them gives up, and mobs don't follow them on stairs. They still count as standing there and seeing (`Taken`, a mob going home unseen). Enemies swap with them like anyone else.
- Mobs and players: each player's `Visit` still has its own copy of the level, as only players' changes differ, and only who is there is shared. A player's id for others (`Client::entity_id`) is their character's, so it is the same when they come back. Other players on the world map are seen within `WORLD_MAP_SIGHT`. A level stays in use while any mob on it isn't at rest, so a chasing mob wanders off and goes home rather than waiting at the stairs. Mobs go by the `ActionClock`, so pausing stops them. A mob after someone who takes stairs in its sight follows if its kind `uses_stairs` (`saw_stairs_taken`, `Doing::Following`, `cross`), carrying the way back, and never onto the world map. A level stays while any of its mobs is away, so they can return. Those not at rest are noted in `LevelSave::unsettled` with each save (`save_mobs`) and carry on when the level is next used; one on another level starts again from home. A level let go of at rest starts them at home, with the same ids.
- A joining character's `Sheet` is what was saved (with attributes worked out from a centred build for a save from before the nine, `Sheet::settled`), what `CreateCharacter` asked for (its `Build` checked, the attributes worked out here), or plain for their kind (`start_sheet`). Attributes never reach anyone else. A mob's speed goes by its rolled attributes.
- A character without `Inventory::outfitted` gets their first clothes on joining (`give_first_clothes`), if human.
- Other levels: on coming into a site (`enter_site`, also on resuming), `send_other_levels` sends each other level the character remembers as a `RememberedLevel`, generating it with its changes. Taking stairs sends none: the client keeps what it had.
- Towns: the whole level is sent on entering, marked `remembered`, after `Buildings`; nothing goes into the character's memory, and `update_sight` only sends cells that have changed since (no sight is worked out).
- A saved world from world map version 5 carries on (6 only turned some desert pois into oases); older ones were wiped with `OLDEST_SAVE_FORMAT` 4 (2026-11-06) and are refused.
- Sites and generator changes: a site keeps the version it was first made with, so a bump alone changes nothing while that version can run. It changes when the site is forgotten (`ServerWorld::forget_site`, `forget_sites`, from `DevForgetMapOnServer`, which delete the files) or its version can't run any more (`make_site` makes it anew). `CharacterWorldSave::site_versions` records the version each character knew: entering one that differs drops their memory of it, and coming back inside one (`resume`) puts them out at the poi (`OnWorldMap`) to go in again. Anyone else inside when a site is forgotten is put out the same way by `handle_messages`; whoever asked for it stays, arriving on the new map on the same level and cell if they can. A world map model always shows the current generator, so it can differ from an older site until that is forgotten.
- Levels are generated again on every visit (and the other level of each staircase, to work out its way down); cheap so far.
- Saves out of reach (`LoadError::CantReach`, say a locked file): `Client::refuse_for_saves` logs it, sends `Refused` and disconnects, whether logging in, joining or going into a site. Nothing is put aside or started again, and a client refused while joining is never `Playing`, so nothing blank is saved over the real character. Only `Broken` starts again. The world itself, either way, stops the server.
- Writing happens on the save thread, so a tick only pays for cloning the save. Stopping: `stop_when_asked` calls `Storage::finish_writing`, and the final clock save goes through the queue as `ServerWorld` is dropped, which the last handle's drop waits for. Tests that look at files must `finish_writing` (or drop) first.
- A plan for Postgres, not built: `docs/context/postgres-migration.md`.
- Uses the filesystem (saves), one reason the web client must not contain it. Its data folder is its own, never shared with a client's (a client's data will go beside it, in `Hall of Worlds/client`).
- Pausing (single player, while the system menu is open): only the clock stops. Ticks, saves and pings carry on, and saving while paused saves the stopped time. Anything added later that goes by game time, such as mobs, must check it. A server opened to other players must turn `pausable` off and carry on.
- Latency is only known on the network thread and only logged, for now. A client can look slower than it is by answering late, so it must never earn anything. Handing it to the game (say, to scale `LEVEL_PRELOAD_STEPS`) is for when something needs it.
- In Docker it is the only process: it serves the web client and the game on port 24691, also on 24690 with `HOW_BEHIND_PROXY=true`, and only there with `HOW_DISABLE_SSL=true` as well (`Dockerfile`).
- A browser checks certificates itself and warns about a self-signed one, which a page can't change. The embedded server never uses TLS: it has no network.
- Characters over the network belong to accounts, and only guests can log in so far; anything else is reached only by tests (`LoginKey::Test`). When an account connects again, the older connection is refused ("playing somewhere else") and saved first, then the new one loads the character: `handle_messages` welcomes a client only once its character is decided (`join`), stopping its messages there for that tick. So an account plays one character at a time. The embedded server's one client has no login, and its character belongs to the account of `LoginKey::SinglePlayer`.
- A character belongs to the server, not a world: its file says which world they are in and holds what they know of each one. Joining (`connections::join`) opens that world (`open_saved`); someone new, or whose world has no save it can run, is put in the home world (logged), and one whose world's save can't be reached is refused. `Client::world` is the world they are in (in the Hall, the one they came from). The systems over every connection go world by world (`connections::systems::for_each_world`, which sorts the clients by world), so players only see, and are told the time of, their own world; everyone in the Hall sees each other whatever world they came from (`entities::in_hall`).
- When embedded in the client, the client's full Bevy features are active too (Cargo unifies features); that's fine.
