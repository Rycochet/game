# shared: site

Sites: the maps world map pois lead to (buildings, walled forts, caves, crypts, towns, farms, herbalists' huts), each one or more levels (`dungeon::Level`) joined by stairs. The poi's kind picks the generator and its options; its map seed decides everything else. Each level is generated on its own, so the client and server agree whichever levels were visited first. Shapes only (walls, doors, floors, ground, water, lava); mobs, items and decorations come later.

## Public API

- `Site::new(kind, seed)` (the generator's current version), `Site::with_version(kind, seed, version) -> Option<Site>` (`None` if that version can't run any more), `Site::with_generator(kind, seed, version, generator)` (the same with other options, such as a ruined building), `.kind()`, `.is_ruined()` (named as a ruin), `.is_building()` (floors go up; otherwise levels go down), `.is_cave()` (its floors swell: `relief`), `.has_basement()` (its last level is below the ground, whatever its index says), `.levels()`, `.level(index) -> SiteLevel` (0 is the one entered from the world map).
- `leads_out(level, x, y)`: whether arriving there leaves for the world map: `Ground` or road on the very edge of the level (beside its rectangle's edge).
- `can_leave(kind, index, level, x, y)`: whether the Up key (`<`, Up / Leave) off stairs takes the player out from there (owner's rule): on level 0 only, from any outside cell (`Cell::is_outside`), but in a cave only where `leads_out` (not a skylight or ground inside the hill).
- `SiteLevel { level, stairs, entrance, buildings, fields, walls }` (`buildings`: a town's, `fields`: a farm's ground floor's, `walls`: a walled fort's or castle's ground floor's, empty elsewhere); `arrival(from: Exit)`: where you arrive coming from the world map (the entrance) or another level (the stairs leading back there); `arrive(from)`: the same, falling back to the first stairs or the entrance (dev tools' jumps between levels).
- `Site::stairs_descend(index, level, stairs) -> (dx, dy)`: the way a staircase goes down, agreeing with the other end (generates the other level to look). Only for looks; moved here from the client so the server can send it.
- `Site::stairs_style(index, stairs) -> StairsStyle`: what a staircase is built as (`Spiral`, `Turning`, `Ladder`, `LogLadder`, `RopeLadder`, `SlatLadder`, `KnottedRope`): from a hash of the seed and the upper level joined, among those suiting the kind (`StairsStyle::choices`), the same at both ends. Only for looks; draws nothing from the generators' sequences, so sites and their golden tests are unchanged.
- `Stairs { x, y, direction, to: Exit }`; `Exit::{WorldMap, Level(n)}`. `StairsDirection` is serde-serialisable (sent in `protocol::SeenStairs`).
- `PoiLook::{Building { outline, width, height, floors, ruin, wall: Option<PoiWall>, castle: Option<PoiCastle> }, Cave { entrance }, Town { buildings }, Farm { width, height, ruin, fields }, Oasis { pools }}`, `PoiLook::of(kind, seed, desert)`: what a site looks like from outside, without generating a level; only what a look from outside shows, as the server sends it to clients.
- `FORGET_BEFORE`: development tool, bump to start clean: servers ignore saves from before it (`server::storage`), and every generator version includes it.
- `Generator::for_site(kind, seed, desert)`: the generator of a real poi's site: `for_poi`, ruined as the seed says (`RUINED_PERCENT`, 30% of buildings, or `DESERT_RUINED_PERCENT`, 60%, in desert (`Poi::desert`, owner); evenly from 1 to 5; never tents or ice shelters). `PoiLook::of` and the server use it, so the model and the site agree.
- `Generator::{Building(BuildingOptions), Cave(CaveOptions), Town(TownOptions), Farm(FarmOptions), Herbalist(HerbalistOptions), Oasis(OasisOptions), DevArea(DevArea)}`, `Generator::for_poi(kind)`: the options per poi kind (wrappers for tuning a generator); `.version()`; `.with_ruin(n)`; `.ruin()`; `Generator::can_be_ruined(kind)`; `MAX_RUIN`.
- `STILTS_VERSION` (`1 + BUILDING_VERSION`): buildings on stilts. A stilt hut saved under `BUILDING_VERSION` stays the plain one-storey hut (`Site::with_generator`) until `FORGET_BEFORE` is next bumped; then that arm goes.
- `BUILDING_VERSION`, `CAVE_VERSION`, `TOWN_VERSION`, `FARM_VERSION`, `HERBALIST_VERSION`, `OASIS_VERSION` (each `1 + FORGET_BEFORE` but caves, `2 + FORGET_BEFORE`; `BOXED_CAVE_VERSION`, caves from before cave mouths were hills, is still run for saved caves): bump when the generator's output changes in a way that matters (not looks), keeping the old version runnable in `with_version` while saved sites use it. The server saves the version each site was first made with. Bumping `FORGET_BEFORE` retires every old version, so their code can be deleted; only `BOXED_CAVE_VERSION` (and the stilt huts' old version) is kept now.
- Walls: `WallMaterial::{Log, Plank, Stone, Block}` (`ALL`, `is_wood`, `pick(seed, weights)`: by a hash, drawing nothing from any sequence); `WallLook { rect, material, gates, towers, gaps }` (the rectangle the 1-cell ring runs round, its own cells included; `has(x, y)`: on the ring and in no tower or gap, `on_ring`, `is_gate`, `moved`), what players are sent (`protocol::ServerMessage::Walls`); `Gate { x, y, runs_east_west }` (`cells`: the west or north door and the one beside it); `WallOptions { percent, gap, pond, materials }`; `PoiWall { west, north, east, south, material, gates }` (ground between footprint and wall per side; gates per side north, east, south, west).
- Castles: `CastleOptions { width, height, gap, pond, moat_percent, moat, wide_moat_from, tower_floors, materials }`; `TowerSpot { x, y, size, by_gate }` (`rect`), `tower_spots(rect)`: where towers stand on a castle's wall round `rect` (the client's world map model uses it too); `PoiCastle { tower_floors, moat }`; `Rect::contains`.
- `BuildingOptions { width, height, outlines, square, min_floors, max_floors, same_size, taper, size_per_floor, ruin, basement_percent, basement_size, windows_percent, ground_windows, stilts, wall, castle }` (`ruin` 0 to 5; 0 is a normal building, and `for_poi` always passes 0 for now), `Outline::{Rectangle, CutCorners, RoundCorners, Circle}`.
- `TownOptions { buildings: (min, max) }` (from the poi's kind: Hamlet 3–8, Village 9–25, Town 26–60, City 61–150). `BuildingLook { id, kind, walls, roof, rects, door, faces }`: what players are sent (`id` is the building's `RoomId`). `TownBuilding { look, quality (0–1000), trades (10–1000, higher in bigger towns) }`: the numbers stay on the server. `BuildingKind::ALL` (23, `name()`), `WallKind::ALL`, `RoofKind::ALL`.
- `FarmOptions { house, fields }`; `FieldLook { rect, livestock, variety }`: the cells sown and what the client needs to choose what grows there; `.contains(x, y)`.
- `HerbalistOptions { house, strips, length }`. A hut's `PoiLook` is a plain `Building`.
- `OasisOptions { size, pools, radius, grass, trees_percent }` (oasis: 40–56 a side, 1–2 pools of radius 5–9, grass 2–4 wide round them, 30% of it trees).
- `CaveOptions { size, levels, entrance, doors, water_percent, lava_percent }`, `CaveEntrance::{Hole, Opening, Either}`.

## Notes

- Windows (owner's rules; `BuildingOptions::windows_percent`, 30% of the places they fit): in a floor's outside walls, on every floor but a basement, with wall on either side along it and none of the building's walls at a diagonal. By hashes and after any ruin, so they move nothing else and no generator version changed; a saved site just gets them. Castles, forts and towers only have them above the ground floor (`ground_windows`, owner), and pyramids never (`windows_percent` 0, owner). Tents and ice shelters have one floor and no ground windows, so none (Claude's choice). Caves, and town buildings' own `BlindWindow`s, are apart from this.
- Buildings (BSP, after RogueBasin's "Basic BSP Dungeon generation"): the outline (cut and rounded corners and circles in integers) gets a 1-cell outer wall (8-neighbour, so diagonals are closed); the inside is split by 1-cell walls, or near the top of the tree by corridors (wall, 1–2 floor, wall); every final part becomes one room filling it to its walls ("rooms expand to fill the space"), following cut corners with a wall round them. Corridors open into the corridor whose wall they end at. Doors are then added (from corridors first) until everything can be reached, plus a few loops; ~8% of doors become secret where nothing depends on them. The ground floor has a 3-cell `Ground` border and outside doors: the first facing south if it can (you arrive on the ground outside it), plus up to one more per 25 cells of width + height (at most 3), on other sides where possible and at least 6 apart. Inside doors only join what the outside doors don't already reach, so a side door may be the only way into part of the building (walk round outside).
- Stilt huts (owner's design; `BuildingOptions::stilts`): two levels of one outline. The ground level is `CoveredGround` across the outline in the usual `Ground` border, with no rooms or doors, lone `Wall` pillars round the outline's edge (`pillars`: at least `PILLAR_SPACING` apart, no randomness) and one ladder (`Ladder` or `LogLadder`); you arrive south of it. Above is an ordinary floor. Ruin: eaten cover becomes `Ground` and the floor over it a hole as usual, and `uncover_ground` then makes ground under any hole `Ground`, so shade matches what is above. Pillars are the only support, so the middle of a ruined hut usually falls in.
- Towers have at least 5 floors, all the same size (`same_size`); one with more may have a top about half the size.
- Castles and forts have at least 3 floors (`min_floors`). Every fort has a basement (`basement_percent` 100, owner).
- Castles (owner, 2026-11-13; `building/castle/`): the outer wall's rectangle is rolled first (40–70 × 36–60, the old footprint), with 5 to 8 cells of courtyard each side (the pond's side widened to fit it and a lane each side), and the keep (the building, at least 3 floors) is what fits inside. Always walled, `Stone` or `Block` by a hash. One gate of 2 doors in the middle of the south side, the way in. Square towers centred on the wall: 7 across on every corner and spaced along each run (one more per 16 cells between towers, `tower_spots`), 2 to 3 floors; 5 across and 2 floors either side of the gate. Each tower is one room per floor with its own stairs (two cells in from opposite corners) and a door into the courtyard on its edge nearest the castle's middle; its upper floors are on the keep's levels (which grow to reach them, filled with what is round the keep's floor), apart from the keep: no wall walk (owner: that waits for drawing lower floors beneath). So on those levels the towers and keep are reached each by their own stairs (the connectivity test starts from every staircase from below). A pond of 3 × 3 to 4 × 4 (or 3 × 3 if that won't fit) in the courtyard, clear of the wall, towers and keep by a cell and not in front of the gate. 60% have a moat 2 to 3 wide (to 4 when the wall's width and height add to 110 or more): water from a bank of 1 cell off the wall and towers to a straight outer edge round them all, towers jutting into it, crossed by a 2-wide `Bridge` from the gate; you arrive past it. Ruins: the keep ruined as any building, the wall gapped as forts' are, and each tower losing its top floor at 15% per step of ruin, then the next while one is left; towers are never taller than the keep's floors left. From their own seeds (`derive("castle")`, `"castle towers"`, `"castle ruin"`, `"castle moat"`, `"castle pond place"`, `"castle pond"`).
- Walled forts (owner, 2026-11-13; `wall.rs`, `building/walled.rs`): half of forts (`FORT_WALL` in `for_poi.rs`) have a 1-cell `Wall` ring (no room) round the ground floor, each side 2 to 8 cells of ground from the building's bounding rectangle, of `Plank` or `Stone` (40 each) or `Log` (20) by a hash of the seed. The gate, 2 `Door`s side by side (put straight in, so `grid::door_nearby` never holds them back), is in the middle of the south side; you arrive just outside it (the entrance moves there). A pond of 2 × 2 to 3 × 3 (`dig_pond`, small blobs) lies on the west, north or east, that side's gap widened to leave a lane of ground to the wall and to the building, so the ground inside stays one walkable ring. Planned from its own seed (`derive("wall")`, `derive("wall pond")`), so the building itself is as it would be unwalled; set round the ground floor last (after any ruin). A ruin's wall has gaps (`ruin_gaps`, from `derive("wall ruin")`: one per 40 cells of ring per step of ruin, each 1 to 3 cells, never a gate's; `Ground`, left out of `WallLook::has`). The level reaches past the wall by 3 cells (`farm::surroundings`). Other doors are never side by side (tested), so any two that are make a gate (`door::gate_partner`). Pyramids taper: each floor 3 to 4 cells smaller per side until the next wouldn't fit a 3 by 3 room and its walls (`taper`, which replaces the other floor rules).
- Stairs are chosen from the top down, as small floors have the fewest places. Bigger floors may have extra staircases to the floor below (`CELLS_PER_EXTRA_STAIRS`, at most `MOST_EXTRA_STAIRS`), each on the same cell of both floors; the server arrives you at the ones you took. Ruin may leave a staircase's end cut off from the rest of a floor, as long as one way up remains from the way in.
- Floors: up to `min(width, height) / size_per_floor` (and `max_floors`), at random. Each floor up has the same outline: half the time the same size, otherwise 1 cell smaller on every side per 10 of the roll above 50 (1–5). Stairs between two floors are on the same cell of both, chosen in the plan well inside the upper floor; splits never put a wall on them, so each floor can be generated alone. Upper floors are wall outside their outline.
- Caves: ellipses filled 60% at random plus a random walk from the centre, smoothed 3 times by the cellular automata rule, keeping what joins the centre (a cave filling its bounding box loses a corner). Joined by a spanning tree of winding passages (2–6 cell stretches, 30% wandering sideways) plus ~25% extra for loops; anything still unreached gets a passage (or, failing that, a dug straight join). Dug dungeons (`doors`) get doors where passages enter caves through 1-wide gaps, ~10% secret. Water (1–3 pools) and lava pools are kept only if everything stays reachable and they don't touch stairs. Every level picks its own size. Way in: a `Hole` (stairs up to the world map in a random cave) or an `Opening` (3-deep `Ground` as wide as the mouth on the south edge, 35% another on the east or west, with 2-wide passages in). Since `CAVE_VERSION`, a cave mouth's top level (only that one: deeper levels and holes are underground in solid rock) is a hill (`outcrop.rs`, owner): rock at least `LEAST_ROCK` (3 to 8, rolled per cave) deep round the open cells, made the convex hull grown by that depth (nothing concave: it looks like a hill and gives the caves' shape away less), worked out in whole numbers; outside it 3 cells of `Ground` (no room) to the level's edge, the mouths' ground gone and each 2-wide passage carried straight out through the rock; the first one's end is the entrance. Stairs down are in the cave furthest (by walking) from where you arrive.
- Ruin (owner's design): the floorplan is the plan's own, and damage has its own seed (`derive("ruin")`), so a building is the same shape at every level. A ruined building's floors depend on each other, so `Plan::new` makes them all, ground up, and keeps them; only a ruined plan does this. Ground floor: each cell next to outside is eaten at 10 × ruin %, then neighbours (4-way, so everything eaten can be walked to) of what was eaten at 10% less, until 0; eaten cells become `Ground` in no room. At ruin 4 and 5 holes also start on floor cells in the middle, 1 per 100 and 1 per 40 floor cells, and nibble out too. Above the ground: beyond the outline and over a gap below are `Hole`, walls included; then the same nibble to `Hole` with ruin minus the storey; then walkable cells over a gap, or more than 4 cells (diagonals count 1) from a wall or door of the floor below, become `Hole`, so the middle of a 9 × 9 room falls in on any ruined upper floor. The 3 × 3 round a staircase is left alone on its own floors and all below. If a floor's arrival can't walk to its stairs up, the floors above it are dropped and those stairs removed, so the level count can be lower than the intact building's. A door with no wall left beside it becomes floor (Claude's choice). Unlike every other site, a ruined upper floor can have floor no one can walk to (rooms cut off by holes; Claude's choice to keep them: they look right and may hold something later). A one-cell hole can be jumped (`movement`), but stairs must connect without jumping, as with liquid. Buildings only go up: there is nothing underground to ruin.
- Skylights: on level 0 of natural caves (no doors), a floor cell becomes `Ground` in no room if a hash of its position says so (1 in 1500), at least 2 cells from liquid, stairs and other outside ground and off the level's edge, so `leads_out` doesn't count it. Nothing else about the level changes. The golden test's RockCave didn't change.
- Towns: a straight road, T or crossroads in the middle (small towns mostly straight, big ones mostly crossroads; 2–4 wide, more in bigger towns), reaching the level's edge so it leads out; a square over the middle from 10 buildings, certain from 50, in the main road's surface. It then grows a plot at a time (owner's design): a plot is chosen from a list, more often an early one, and something goes beside it: further along the road (touching or with a 1–2 cell alley of bare ground, often lined up at the back; the road extends in front of it, unless it is a main road or a square's edge, which stay as they are), across the road lined up with one end, a house behind it with its door away (from 15 buildings, up to 20% of the town), or round a corner on a new side road along its flank (from 8 buildings; no better than the road it leaves; much likelier once a road has 8 tiles of frontage since its last). A building can't join a straight line of building that has reached 10 cells (or join two that make 10 together), so it leaves a gap; it may itself take a line past 10. Roads only go over bare ground, never over another road, and never beside a parallel road without 3 cells between (room for a building). After the level is cut down, any road reaching the border carries on to its edge. A plot with nothing left beside it leaves the list; when the list is empty a new one starts as near the middle as there is room. One garden per ~25 plots, smallest side the larger of 3 and buildings ÷ 20, never touching another. L, T and H shapes in plots at least 5 × 5, keeping every cell in a 2 × 2 of the building and the door's stretch whole. Anything walled in loses a neighbouring building. The level is cut down to what is used plus a 3-cell border. Which road, wall and roof is weighted by size (`blend`).
- Town kinds, after the layout: houses first (all not on a road, then others up to 30%), so more than 30% is possible; then by weight with a minimum town size per kind (cathedral 50), each copy halving that kind's weight, and past a twentieth of the town far faster; the first is always a shrine or inn. Walls, roof, quality, trades and windows come from hashes (seed, building number), not the layout's sequence, so adding more moves nothing.
- Farms (owner's design): a house of 2 floors, half with a basement, with 1 to 8 of the 8 places round it (a 3 × 3 grid with the house in the middle) used. Fields are rectangles of at least 8 × 8 sown cells with a `Fence` ring of their own, so 10 across; one `FieldGate`, never on a corner, as near the entrance as the fence's sides get. `LANE` (2) of ground lies between the yard and every field, and fields are in places apart, so a jumped fence always has somewhere to land, and nothing comes within the house's own 3-cell border. A third of farms with 2 or more places have a pond in one instead: blobs of `Water` in one piece, no fence, with any land enclosed filled in so all stays reachable. Half are all crops, a quarter all pasture, the rest choose per field. Dirt tracks (Claude's addition): the shortest way over ground from the entrance to the nearest edge, then from each gate to the nearest track, never over eaten parts of the house. Ruined: the house as usual, and fences lose stretches (`FENCE_GAP_PERCENT` × ruin %, up to 3 cells, to `Ground`), gates kept. The ground floor's level reaches into negative coordinates; the house's cells keep theirs, so stairs line up with the floors above, whose levels are smaller.
- Herbalists' huts (owner's design): one storey, 5 to 8 a side, always a basement of 8 to 16 a side or the hut's size if bigger, never smaller. One patch of 3 to 5 parallel strips of `HerbBed`, 7 to 12 long, 1 apart, straight against the hut's yard on a side not facing its door. Claude's choices: strips and the ground between are walkable, no fence, no track, either way round; a ruin's patch is left as it is.
- Oases (owner's design): one level of `Ground` (drawn the land's own colour, so desert sand) with 1 or 2 elliptical pools of `Water` in the middle, each ringed by `Grass`, of which a share are `Tree`s by a hash of the place. The way in is the middle of the south edge. Trees cutting ground off fall to grass, one at a time, and grass still cut off (an island) becomes water, so everything is reachable.
- Basements (`BuildingOptions::basement_percent`, farms and huts): the last level, whatever floors a ruin has lost (the ground floor's stairs are pointed at it after ruin), with the ground floor's outline or a bigger rectangle round it (`basement_size`; its level then reaches further than the ground floor's own) and no outside doors. Never ruined. The 3 × 3 round its stairs stays on the ground floor. Numbering is the client's: `LevelInfo::storey`.
- Rooms: every building room and cave has a `RoomId` on its cells (water and lava in a cave keep it); corridors, passages, doors and ground have none.
- Every walkable cell is reachable from where you arrive, without secret doors or crossing water/lava (tested for every kind).
- Changing any constant, the order of random draws, or the kind table changes every site: the golden test fails on purpose.
