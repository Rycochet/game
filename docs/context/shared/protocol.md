# shared: protocol

The messages between clients and the server, and the `Link` that carries them. Clients send intents; the server sends what the player may know. Design: "Map data" in `architecture.md`.

## Files

- `crates/shared/src/protocol/mod.rs`: `PROTOCOL_VERSION`, world map range constants, `ClientMessage`, `ServerMessage`, `WorldInfo`, `WorldChunk`. Tests: every message survives the link; closed links; report distance below the preload. Beside it: `client_message.rs`, `dev_tool.rs` (`ClientMessage::is_dev_tool`), `server_message.rs`, `ping.rs` (pings and pongs as bytes), `world_chunk.rs` (`WorldChunk`, `SeenPoi`, `WorldInfo`).
- `crates/shared/src/protocol/combat.rs`: `Landed`.
- `crates/shared/src/protocol/level.rs`: site levels as sent: `LEVEL_CHUNK_SIZE` (8), `ENTER_REACH` (2), `level_chunk(x, y) -> (chunk, bit)`, `LevelInfo`, `LevelChunk` (`positions()`, `cells()`), `RememberedLevel`, `SeenStairs`. Test: cells come back where they were.
- `crates/shared/src/protocol/online.rs`: `OnlineSettings` (name, public address, bind address, port, player limit, `upnp` (off by default, also for settings saved before it; `HOW_UPNP` wins over it); by default "Hall of Worlds", `0.0.0.0`, `DEFAULT_PORT`, no limit; `move_off_old_default` turns a saved 8081, the old default, into `DEFAULT_PORT`, which `Preferences` does on loading), `OnlineState` (`Offline`, `Online { certificate, fingerprint, router }`, `Failed(reason)`), `RouterPort` (`Off`, `Opening`, `Open { external, shared }` (`shared`: the router's own address is private or the provider's, CGNAT), `Failed(reason)`), for `ClientMessage::SetOnline(Option<OnlineSettings>)` (the embedded server's host only) and `ServerMessage::Online`; `ServerMessage::GoingOffline(name)` tells others it closed on purpose.
- `crates/shared/src/protocol/version.rs`: `VERSION_PATH` (`/_version`), `GAME_NAME` ("Hall of Worlds", the magic value telling a HOW server from other web servers), `ServerVersion { game, version, protocol }` (`this()`, `to_json`, `from_json` (`None` unless it parses and `game` is `GAME_NAME`), `compatible` (same `PROTOCOL_VERSION`)): JSON through `serde_json`, so `shared` depends on it. Tests.
- `crates/shared/src/protocol/address.rs`: `ServerAddress` (`parse` what players type: host name, IPv4 or `[IPv6]`, optional port, no scheme or path; shown as typed, the port only when not `DEFAULT_PORT`; `url()` its `wss://host:port/ws`), `DEFAULT_PORT` (24691, the secure port), `FALLBACK_PORT` (443); `ports_to_try(text)` (the port typed, or `DEFAULT_PORT` then `FALLBACK_PORT`), `at_port`, `with_port()` (always with the port: how Connect saves a checked server), `version_url()` (`https://host:port/_version`). Tests.
- `crates/shared/src/protocol/link.rs`: `Link`, `ClientLink`, `ServerLink`, `LinkError`, `local_pair`, `Wire`, `wired`. Tests (in `mod.rs`): every message survives the link and a wire, garbled bytes and closed ends noticed.
- `crates/shared/src/protocol/login.rs`: between `Hello` and `Welcome`: `LoginMethod`, `Credentials`, `GuestToken` (32 bytes; `to_hex`, `from_hex`; its `Debug` hides it), `CharacterId(Id)` (a UUID, so always a safe file name), `CharacterSummary { id, name, last_played }`. Tests: tokens read back and stay out of logs, safe ids.

`Welcome` carries the character's name, the world's `WorldTime` and the server's clock (real seconds); `Pong` and `Paused` carry the server's clock, which every world's time is worked out from, and `WorldClock(WorldTime)` says a world's time has been moved or sped up (`DevSetWorldClock { minutes?, rate? }`, to everyone in it); `Hour` says a new whole hour has begun (the tide); `Ping { sent }` is answered by `Pong { sent, clock }`. `ClientMessage::ping_bytes` / `read_ping` and `ServerMessage::pong_bytes` / `read_pong` work on the bytes, so whatever carries them (the client's socket, the server's network thread) can deal with these two itself, for timing that doesn't depend on the game's frames or ticks.

## Public API

- `SOCKET_PATH` (`/ws`): where a server's WebSocket is.
- `VERSION_PATH` (`/_version`), `GAME_NAME`, `ServerVersion`: what a server says it is, so a client can check an address is a Hall of Worlds server speaking its protocol before connecting.
- `PROTOCOL_VERSION`: bump whenever a message changes; the server refuses other versions.
- Combat (55): `ClientMessage::UseAbility { ability, target }` (answered with `AbilityStarted` or nothing), `CancelAbility` (one winding up), `WithdrawAbility` (one still waiting in `Client::waiting` for the energy; not answered, never one begun); `ServerMessage::AbilityStarted { who, ability, target, lands_in, ready_in }` (`who` and `target` `None` meaning the player; ticks from now), `AbilityLanded { who, target, landed: Landed }` (`Landed::{Hit { harm, left }, Fizzled, Cancelled}`, `left` per mille for health bars), `Killed`. A player is told of their own abilities and of those aimed at them.
- `WORLD_MAP_SIGHT` (300): how far (each way) the client may show anything on the world map. `WORLD_MAP_PRELOAD` (one chunk, 64): how much further the server sends.
- `ClientMessage::GiveItem { item, to }`: something carried to a mob within `mob::GIVE_REACH` and in sight; answered with `Inventory`, and the mob's `EntitySeen` again if its feeling changed.
- `ClientMessage::MoveItem { item, to, x, y, rotation }`: something carried to this place in this grid; `StackItem { item, onto }` (as much of a carried stack as fits onto another that looks the same, from its top); in these and in `GiveItem`, `WearItem` and `DropItem`, an id from inside a stack stands for it and everything above it (splitting: `Inventory::part_of`); `FromStack { stack, items, then }` wraps one of them for a group from a mixed stack (`Inventory::lift_group`); `SortGrid { holder }` (`Inventory::sort_grid`: stacked, then laid out again largest first, or nothing if something wouldn't fit); `BinItem { item }` (with all in it, destroying what was there); `WearItem { item }`; `DevGiveItem { kind, size, magical, quality, set, favour, seed, count, identical, request }` (rolled by `item_form::try_make_item` from `seed` with the `RollRequest`, nothing given if any is refused, or a random one; `count` kept to the server's `StackLimits`) and `DevSetCreature { kind, how }` (dev tools; `KindChange::{Permanent, Temporary}`, `kind_change.rs`). `DevDeleteCharacter` (dev tools): the character's save is deleted and the account given a new character, answered with `Characters` with none to choose, as on first joining. All answered with `ServerMessage::Inventory` (also sent after `Welcome`, with `Sheet` and `VisitedGates`, only ever about the player's own character), whether or not they could be done, so the client is put right.
- `ServerMessage::EntitySeen(EntityLook)`, `EntityMoved { id, x, y }`, `EntityGone { id, died }`: mobs and other players coming into sight, moving and going, only while in the player's sight; `died` when it went by dying, which only those who could see it are told (`ServerWorld::died`). `EntitySeen` is sent again when what can be seen of what one wears changes, as for its feeling. A map change forgets them on both sides. An `EntityMoved` is about 24 bytes.
- `ClientMessage::ActionBar(BarChange)`: change the action bar (`shared::ability`); always answered with `ServerMessage::ActionBar(ActionBar)`, the bar as it now is, so a refused change is put right. `ActionBar` is also sent on joining, after `Sheet`.
- `ClientMessage::DevDetectMonsters(bool)` (dev tools): every mob on the level is told of, seen or not.
- `ClientMessage::DevTruesight(bool)` (dev tools): items' secrets and secret doors are sent, without being found out. Answered with `Inventory`, what is on the ground under the player is told again, and the level is sent again if it has secret doors (which closes panels on it).
- `ClientMessage::DevGodMode(bool)` (dev tools): mobs take no notice of the character, who can walk through them.
- `ClientMessage::DevKillMob { mob }` (dev tools): a mob in sight dies; what it had falls where it stood.
- `ClientMessage::DevSkills(DevSkills::{LearnSome, Forget})` (dev tools: `DEV_SKILLS_LEARNT` random ends of branches practised, or back to the kind's starting skills): answered with `Sheet`.
- `ClientMessage::DevVitals(DevVitals::{Hurt(n), SpendMana(n), Fill, Bonus})` (dev tools; `DEV_BONUS` 5 for `DEV_BONUS_TICKS`, 5 minutes): answered with `Vitals`.
- `ServerMessage::Vitals { who, health, mana }` (`shared::vitals::VitalNow` each): `who` is `None` for the player's own, after `Sheet` in every welcome and whenever how much there is or can be changes other than by refilling, which the client works out itself; a party member's id later (owner, 2026-11-06).
- `ServerMessage::Keepers`: who keeps each shop of a town level, after `Buildings`. `ClientMessage::OpenTrade { with }`: trade with someone (a shop's keeper, from beside its door), after any steps to get there. Answered with `ServerMessage::TradeStock { with, items }` if it can be, otherwise with nothing. `GiveItem` to a keeper also answers with `TradeStock` after `Inventory`. `ClientMessage::TakeItem { with, item, to, x, y, rotation }`: take from them, answered with both whether or not it could be done.
- `ClientMessage::LookUpItems(ids)`: what these items are, for showing them where they are written into text (`shared::item_text`); at most `MOST_LOOKED_UP` (64) a tick are looked up, the rest ignored. Answered with `ServerMessage::ItemsLookedUp { found, unknown }`: each found item alone (nothing in it or stacked on it), secrets hidden as in `Inventory`, never where it is; `unknown`, the ids found nowhere loaded.
- `ClientMessage::DropItem { item }`, `TakeFromGround { item, to, x, y, rotation }`, `StackFromGround { item, onto }` (as much as fits onto a carried stack, the rest staying on the ground), `WearFromGround { item }`, `BinFromGround { item }`: the ground under the player, in a site, queued behind their steps. Answered with `Inventory` and `ServerMessage::GroundItems { x, y, items }`, whether or not it could be done; `GroundItems` is also sent on arriving on a cell with something on it, leaving one, or when someone else changes it, and only to who stands there (empty once there is nothing).
- `ServerMessage::GroundSeen { x, y, load }`, `GroundGone { x, y }`: bags in sight that differ from what the character remembers, and all they remember on arriving on a level. Out of sight nothing is said.
- `ClientMessage::SetPaused(bool)`: stop or restart the server's clock, and every world's time with it, answered with `ServerMessage::Paused { paused, clock }` by a server that can (`Welcome`'s `can_pause`), ignored by others. `ClientMessage::DevSnowLine(n)` (dev tools: answered with `SnowLine`). `ClientMessage::Hello { protocol, makes_characters }`: the first message on a connection; `makes_characters` (the client has a creation screen) has a new guest's or single player's character made first: `Characters` with none to choose, then `CreateCharacter`, which names their one character. `Login(Credentials)`, after `LoginOptions`. `ChooseCharacter { id }` and `CreateCharacter { name, kind, appearance, build }`, after `Characters` (refused unless the kind is playable, the look suits it and the `sheet::Build` is valid; the server works out the attributes; client `character_create` sends it). `ClientMessage::Step { map, number, step }`: a step (`movement::Step`) on the current map; `map` counts the maps the server has put the player on since `Welcome` (each `EnterLevel`, `EnterHall`, `OnWorldMap` and `Teleported`), so steps meant for the last map are ignored; `number` counts the client's steps. `EnterSite { chunk }` (the player must be within `ENTER_REACH` of its poi), `EnterGate { entrance }` (through that World Gate of the world, within `ENTER_REACH` of it on the world map, into the Hall before the gate it leads to; waits behind steps), `UseExit` (the stairs or edge ground the player stands on), `Explore` (into the wilderness where the player stands on the world map; refused in water), `LeaveWilderness` (onto the world map from outside ground in the wilderness, not into water), Dev tools, only accepted by an embedded server (others ignore them; `is_dev_tool()`): `DevToShowcase` (to `shared::showcase`'s plain), `DevGoToWorld { seed }` (to that seed's world, where the player was on its map or at one of its World Gates if new there; answered with a fresh `Welcome` and `OnWorldMap`), `DevToHall` (to the Hall of Worlds, before the gate to the World Gate nearest the player, or the Hall's first gate; answered with `EnterHall`), `DevTeleport { x, y }` (to a point on the current map, in a site only a walkable cell; answered with `Teleported`), `DevBackToStart` (to the nearest World Gate on the world map, where characters arrive, out of any site; answered with `OnWorldMap`), `DevEnterSite { kind, seed, level }`, `DevForgetMap`, `DevForgetMapOnServer` (the server forgets the site, or on the world map all of them; anyone else in one is put out with `OnWorldMap`), `DevGenerateSite { kind, seed, ruin }` (a made-up site as if new, entered where the player stands).
- `ServerMessage::LoginOptions { methods }` (the answer to `Hello`; an embedded server goes straight to `Welcome`), `Characters { list, can_create }` (the answer to an account's `Login`; a guest goes straight to `Welcome`), `Hour(hour)` (a new game hour, which sets the tide), `SnowLine(n)` (the snow line has moved), `WorldClock(time)` (the world's time was moved or sped up), `EnterLevel`'s `LevelInfo::kind` is a `LevelKind` (`Poi(kind)`, `Hall { origin }`, which the client makes itself with `EnterHall`'s origin, or `Wilderness`, whose bounds are a window round the player that `ServerMessage::WildernessWindow { bounds }` moves without it being a new map: the client keeps what it has; `ServerMessage::InPoi(Option<PoiKind>)` says which poi's cutout the player stands in there, after `EnterLevel` and whenever it changes; `poi()`, `is_town()`). `WorldInfo { id, terrain_seed, world_map_version, gates }` (`gates`: `GateInfo { entrance, x, y, place }`, each World Gate and the Hall gate number it leads to, whose looks it shares; only the Hall's planets have any). `Welcome { world: WorldInfo, time, server_clock, snow_line, x, y, dev_tools, can_pause, stacks }` (`stacks`: the server's `StackLimits`; the world, its time and the server's clock now, its snow line, and where the player is on its world map: where they left off; `EnterLevel` follows if they were in a site), `Refused(reason)`, `WorldChunk(WorldChunk)`, `EnterLevel(LevelInfo)` (the player is now on this level: kind, building or not, index of how many, whether the last is a basement (`storey(index)`: how high a level is, -1 for that), bounds, arrival cell, and `entering_site`: come into the site or back on joining, rather than by its stairs), `Buildings(Vec<BuildingLook>)` (a town's, after `EnterLevel` and before its cells), `Fields(Vec<FieldLook>)` (a farm's ground floor's, likewise), `LevelCells(LevelChunk)`, `RememberedLevel { index, bounds, chunks }` (what the character remembers of another level of the site, with the neighbours that shape it, after `EnterLevel` when `entering_site`; for the maps), `EnterHall { x, y, origin }` (in the Hall of Worlds, `shared::hall`, here: the client works out its cells itself; a map like any other; every position in the Hall, this, `Position`, `Teleported`, entities and `DevTeleport`, counts from `origin`, a multiple of `GATE_SPACING`, as the Hall's own `x` runs to billions, more than drawing can place), `OnWorldMap { x, y }` (on the world map: out of a site at the poi, or back to the start), `Teleported { x, y }` (dev tools: jumped to here on the current map), `Position { map, step, x, y }` (where the server has the player once it has dealt with step `step`, sent once a tick when steps arrived: the client adds its later steps and moves the player there if it shows them elsewhere).
- `ServerMessage::VisitedGates(places)`: every World Gate pair the character has gone through, either way, as `hall::GatePlace::number`s; after `Welcome` and whenever one is added (the client draws their water orange).
- `ServerMessage::Road(Road)` (`shared::road`): a road between two towns, sent once per connection by the server's road thread to anyone near enough; the client keeps it.
- `WorldInfo { id, terrain_seed, world_map_version }`.
- `WorldChunk { chunk, poi: Option<SeenPoi> }`: what the player knows of a world map chunk (no terrain: the client generates it). `SeenPoi { kind, look, chunk, x, y }` (`From<Poi>`): never the map seed; `look` is `site::PoiLook`. A chunk's `poi` is `None` for a poi the character doesn't know of, as if there were none. Later: the chunk's changes and per-player state (visited, attitude).
- `SeenStairs`: where, which way, `descends`, `style`, and `open_to_sky` (its top end is out in the open: on the world map, or on outside ground above).
- `LevelChunk { chunk, mask: u64, cells, stairs, remembered }`: some cells of an 8×8 chunk (bit `row × 8 + column`), as the player would see them (secret doors are wall), with the stairs on them; `remembered` for cells seen on an earlier visit, sent on arriving. `SeenStairs { x, y, direction, descends, style }`: where stairs lead stays with the server.
- `local_pair() -> (ClientLink, ServerLink)`: an in-process connection. `wired() -> (Link, Wire)`: a link whose bytes a `Wire` carries elsewhere (a WebSocket): `deliver(bytes)`, `take()`, or `into_parts()` (a sender for incoming bytes and a receiver of outgoing ones, for different threads); either side going is noticed by the other. `Link::send(&msg) -> bool` (`false` once the other end has gone), `Link::receive() -> Result<Option<msg>, LinkError>` (`Closed`, `Garbled`); never blocks.

## Notes

- A `Link` carries postcard-encoded bytes, not the messages, also in single player: nothing can be shared between client and server by accident, and over the network the same bytes are one WebSocket binary message each.
- When adding a message, add one of it to the round-trip test (`every_message`).
- Compiles for wasm: the web client uses the same types and `wired()` links over the browser's WebSocket.
