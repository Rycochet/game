# shared: protocol

The messages between clients and the server, and the `Link` that carries them. Clients send intents; the server sends what the player may know. Design: "Map data" in `architecture.md`.

## Files

- `crates/shared/src/protocol/mod.rs`: `PROTOCOL_VERSION`, world map range constants, `ClientMessage`, `ServerMessage`, `WorldInfo`, `WorldChunk`. Tests: every message survives the link; closed links; report distance below the preload. Beside it: `client_message.rs`, `server_message.rs`, `ping.rs` (pings and pongs as bytes), `world_chunk.rs` (`WorldChunk`, `SeenPoi`, `WorldInfo`).
- `crates/shared/src/protocol/level.rs`: site levels as sent: `LEVEL_CHUNK_SIZE` (8), `ENTER_REACH` (2), `level_chunk(x, y) -> (chunk, bit)`, `LevelInfo`, `LevelChunk` (`positions()`, `cells()`), `RememberedLevel`, `SeenStairs`. Test: cells come back where they were.
- `crates/shared/src/protocol/online.rs`: `OnlineSettings` (name, public address, bind address, port, player limit; by default "Hall of Worlds", `0.0.0.0`, `DEFAULT_PORT`, no limit), `OnlineState` (`Offline`, `Online { certificate, fingerprint }`, `Failed(reason)`), for `ClientMessage::SetOnline(Option<OnlineSettings>)` (the embedded server's host only) and `ServerMessage::Online`; `ServerMessage::GoingOffline(name)` tells others it closed on purpose.
- `crates/shared/src/protocol/address.rs`: `ServerAddress` (`parse` what players type: host name, IPv4 or `[IPv6]`, optional port, no scheme or path; shown as typed, the port only when not `DEFAULT_PORT`; `url()` its `wss://host:port/ws`), `DEFAULT_PORT` (8081, the secure port). Tests.
- `crates/shared/src/protocol/link.rs`: `Link`, `ClientLink`, `ServerLink`, `LinkError`, `local_pair`, `Wire`, `wired`. Tests (in `mod.rs`): every message survives the link and a wire, garbled bytes and closed ends noticed.
- `crates/shared/src/protocol/login.rs`: between `Hello` and `Welcome`: `LoginMethod`, `Credentials`, `GuestToken` (32 bytes; `to_hex`, `from_hex`; its `Debug` hides it), `CharacterId(Id)` (a UUID, so always a safe file name), `CharacterSummary { id, name, last_played }`. Tests: tokens read back and stay out of logs, safe ids.

`Welcome` carries the world's float clock, in game minutes, as do `Pong` and `Clock` (it has been moved: `DevSetTime`); `Hour` says a new whole hour has begun (the tide); `Ping { sent }` is answered by `Pong { sent, clock }`. `ClientMessage::ping_bytes` / `read_ping` and `ServerMessage::pong_bytes` / `read_pong` work on the bytes, so whatever carries them (the client's socket, the server's network thread) can deal with these two itself, for timing that doesn't depend on the game's frames or ticks.

## Public API

- `SOCKET_PATH` (`/ws`): where a server's WebSocket is.
- `PROTOCOL_VERSION`: bump whenever a message changes; the server refuses other versions.
- `WORLD_MAP_SIGHT` (300): how far (each way) the client may show anything on the world map. `WORLD_MAP_PRELOAD` (one chunk, 64): how much further the server sends.
- `ClientMessage::GiveItem { item, to }`: something carried to a mob within `mob::GIVE_REACH` and in sight; answered with `Inventory`, and the mob's `EntitySeen` again if its feeling changed.
- `ClientMessage::MoveItem { item, to, x, y, rotation }`: something carried to this place in this grid; `StackItem { item, onto }` (as much of a carried stack as fits onto another that looks the same, from its top); `BinItem { item }` (with all in it, destroying what was there); `WearItem { item }`; `DevGiveItem { kind, size, magical }` and `DevSetCreature(kind)` (dev tools). All answered with `ServerMessage::Inventory` (also sent after `Welcome`, with `Sheet`, only ever about the player's own character), whether or not they could be done, so the client is put right.
- `ServerMessage::EntitySeen(EntityLook)`, `EntityMoved { id, x, y }`, `EntityGone { id }`: mobs and other players coming into sight, moving and going, only while in the player's sight. A map change forgets them on both sides. An `EntityMoved` is about 24 bytes.
- `ClientMessage::DevDetectMonsters(bool)` (dev tools): every mob on the level is told of, seen or not.
- `ClientMessage::DevTruesight(bool)` (dev tools): items' secrets and secret doors are sent, without being found out. Answered with `Inventory`, what is on the ground under the player is told again, and the level is sent again if it has secret doors (which closes panels on it).
- `ClientMessage::DevGodMode(bool)` (dev tools): mobs take no notice of the character, who can walk through them.
- `ClientMessage::DevKillMob { mob }` (dev tools): a mob in sight dies; what it had falls where it stood.
- `ServerMessage::Keepers`: who keeps each shop of a town level, after `Buildings`. `ClientMessage::OpenTrade { with }`: trade with someone (a shop's keeper, from beside its door), after any steps to get there. Answered with `ServerMessage::TradeStock { with, items }` if it can be, otherwise with nothing. `GiveItem` to a keeper also answers with `TradeStock` after `Inventory`. `ClientMessage::TakeItem { with, item, to, x, y, rotation }`: take from them, answered with both whether or not it could be done.
- `ClientMessage::DropItem { item }`, `TakeFromGround { item, to, x, y, rotation }`, `StackFromGround { item, onto }` (as much as fits onto a carried stack, the rest staying on the ground), `WearFromGround { item }`, `BinFromGround { item }`: the ground under the player, in a site, queued behind their steps. Answered with `Inventory` and `ServerMessage::GroundItems { x, y, items }`, whether or not it could be done; `GroundItems` is also sent on arriving on a cell with something on it, leaving one, or when someone else changes it, and only to who stands there (empty once there is nothing).
- `ServerMessage::GroundSeen { x, y, load }`, `GroundGone { x, y }`: bags in sight that differ from what the character remembers, and all they remember on arriving on a level. Out of sight nothing is said.
- `ClientMessage::SetPaused(bool)`: stop or restart the world's clock, answered with `ServerMessage::Paused { paused, clock }` by a server that can (`Welcome`'s `can_pause`), ignored by others. `ClientMessage::DevSnowLine(n)` (dev tools: answered with `SnowLine`). `ClientMessage::Hello { protocol }`: the first message on a connection. `Login(Credentials)`, after `LoginOptions`. `ChooseCharacter { id }` and `CreateCharacter { name, kind, appearance }`, after `Characters` (refused unless the kind is playable and the look suits it; no menu sends it yet). `ClientMessage::Step { map, number, step }`: a step (`movement::Step`) on the current map; `map` counts the maps the server has put the player on since `Welcome` (each `EnterLevel`, `OnWorldMap` and `Teleported`), so steps meant for the last map are ignored; `number` counts the client's steps. `EnterSite { chunk }` (the player must be within `ENTER_REACH` of its poi), `UseExit` (the stairs or edge ground the player stands on), Dev tools, only accepted by an embedded server (others ignore them; `is_dev_tool()`): `DevToShowcase` (to `shared::showcase`'s plain), `DevTeleport { x, y }` (to a point on the current map, in a site only a walkable cell; answered with `Teleported`), `DevBackToStart` (to where new characters start on the world map, out of any site; answered with `OnWorldMap`), `DevEnterSite { kind, seed, level }`, `DevForgetMap`, `DevForgetMapOnServer` (the server forgets the site, or on the world map all of them; anyone else in one is put out with `OnWorldMap`), `DevGenerateSite { kind, seed, ruin }` (a made-up site as if new, entered where the player stands).
- `ServerMessage::LoginOptions { methods }` (the answer to `Hello`; an embedded server goes straight to `Welcome`), `Characters { list, can_create }` (the answer to an account's `Login`; a guest goes straight to `Welcome`), `Hour(hour)` (a new game hour, which sets the tide), `SnowLine(n)` (the snow line has moved), `Clock(minutes)` (the clock was moved), `Welcome { world: WorldInfo, clock, snow_line, x, y, dev_tools, can_pause, stacks }` (`stacks`: the server's `StackLimits`; the world, its clock in game minutes and snow line, and where the player is on its world map: where they left off; `EnterLevel` follows if they were in a site), `Refused(reason)`, `WorldChunk(WorldChunk)`, `EnterLevel(LevelInfo)` (the player is now on this level: kind, building or not, index of how many, whether the last is a basement (`storey(index)`: how high a level is, -1 for that), bounds, arrival cell, and `entering_site`: come into the site or back on joining, rather than by its stairs), `Buildings(Vec<BuildingLook>)` (a town's, after `EnterLevel` and before its cells), `Fields(Vec<FieldLook>)` (a farm's ground floor's, likewise), `LevelCells(LevelChunk)`, `RememberedLevel { index, bounds, chunks }` (what the character remembers of another level of the site, with the neighbours that shape it, after `EnterLevel` when `entering_site`; for the maps), `OnWorldMap { x, y }` (on the world map: out of a site at the poi, or back to the start), `Teleported { x, y }` (dev tools: jumped to here on the current map), `Position { map, step, x, y }` (where the server has the player once it has dealt with step `step`, sent once a tick when steps arrived: the client adds its later steps and moves the player there if it shows them elsewhere).
- `WorldInfo { id, terrain_seed, world_map_version }`.
- `WorldChunk { chunk, poi: Option<SeenPoi> }`: what the player knows of a world map chunk (no terrain: the client generates it). `SeenPoi { kind, look, chunk, x, y }` (`From<Poi>`): never the map seed; `look` is `site::PoiLook`. A chunk's `poi` is `None` for a poi the character doesn't know of, as if there were none. Later: the chunk's changes and per-player state (visited, attitude).
- `SeenStairs`: where, which way, `descends`, `style`, and `open_to_sky` (its top end is out in the open: on the world map, or on outside ground above).
- `LevelChunk { chunk, mask: u64, cells, stairs, remembered }`: some cells of an 8×8 chunk (bit `row × 8 + column`), as the player would see them (secret doors are wall), with the stairs on them; `remembered` for cells seen on an earlier visit, sent on arriving. `SeenStairs { x, y, direction, descends, style }`: where stairs lead stays with the server.
- `local_pair() -> (ClientLink, ServerLink)`: an in-process connection. `wired() -> (Link, Wire)`: a link whose bytes a `Wire` carries elsewhere (a WebSocket): `deliver(bytes)`, `take()`, or `into_parts()` (a sender for incoming bytes and a receiver of outgoing ones, for different threads); either side going is noticed by the other. `Link::send(&msg) -> bool` (`false` once the other end has gone), `Link::receive() -> Result<Option<msg>, LinkError>` (`Closed`, `Garbled`); never blocks.

## Notes

- A `Link` carries postcard-encoded bytes, not the messages, also in single player: nothing can be shared between client and server by accident, and over the network the same bytes are one WebSocket binary message each.
- When adding a message, add one of it to the round-trip test (`every_message`).
- Compiles for wasm: the web client uses the same types and `wired()` links over the browser's WebSocket.
