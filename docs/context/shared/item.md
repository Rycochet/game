# shared: item

Ids, kinds of item, and carrying items in grids: the rules both sides check moves by. The server is the only place ids and new items come from.

## Files

- `crates/shared/src/id.rs`: `Id`, a version 6 UUID (text in saves, 16 bytes in messages). Nothing here makes one: `server::ids::new_id` does.
- `crates/shared/src/item.rs`: the module list, the re-exports below (every type is used as `item::X`) and the constants `MAX_SHAPE_SIDE`, `MAX_DEPTH`, `POCKETS`. Tests for every rule below in `item/tests.rs`, `item/add_tests.rs` and `item/stack_tests.rs`. In `item/`:
  - `kind.rs`: `ItemKind` (`ALL`, `blade_family`, `comes_in_sizes` and other questions about a kind). `def.rs`: `ItemKind::def`, the table of what each kind is. `category.rs`: `ItemCategory`, `ItemKind::category`. `item_def.rs`: `ItemDef`, `ContainerDef`, `WearDef`, and the helpers the table is written with (`plain`, `bag`, `wear`, `taking`, `worn`).
  - `item.rs`: `Item` (`new`, `name`, `shape`, `total_weight`, `set_gems`), `MadeAt`. `made.rs`: `Made`. `quality.rs`: `Quality`, `artifact_name`. `secrets.rs`: `Favour`, `Known`, and `Item`'s magic and secrets (`can_be_magical`, `roll_secrets`, `hide_secrets`).
  - `stack.rs`: `StackLimits`, and `Item`'s stacks (`count`, `top`, `members`, `groups`, `looks_like`, `is_even`, `take_top`, `split_top`, `put_on`, `own_weight`).
  - `placed.rs`: `Placed`, `Holder`. `refused.rs`: `MoveRefused`. `shape.rs`: `Shape`, `Rotation`. `drop.rs`: `Drop`, `ODDS_OUT_OF`, `roll_drop`.
  - `inventory.rs`: `Inventory`, its weights. `inventory/`: `lookup.rs` (`find`, `grid`, `placed`, what holds what), `rules.rs` (`check_move`, `check_add`, the rules below), `changes.rs` (`add`, `move_item`, the bin), `room.rs` (`first_place_for`, `give`), `stacking.rs` (`stack_room`, `stack_onto`, `add_to_stack`, `first_stack_for`, taking a stack's top), `parts.rs` (`part_of`, `lift_part`, `lift_group`, `settle_parts`), `cost.rs` (`move_cost`, `put_down_cost`), `sort.rs` (`sorted_grid`, `sort_grid`).
- `crates/shared/src/item_form.rs`: `ItemForm` and the module list, re-exporting the types below. Tests. In `item_form/`:
  - `give.rs`: `give_form`, `give_blade_within`, `give_commission`. `armour.rs`: rolling a new armour item's form by its kind. `limits.rs`: `Limits`.
  - `gem.rs`: `GemForm`, `Cut`, rolling a gem. `ring.rs`: `RingForm`, `Setting` and the band's parts. `ring_roll.rs`: rolling a ring and its gems. `words.rs`: words for a ring's name (its gems counted, plurals).
  - `measure.rs`: `ItemForm::shape` and `grams_at`, for forms that decide their item's cells and weight.
- `crates/shared/src/material.rs`: `Material`, `Category`. Placeholder table, first guesses at tiers. Tests.

## Public API

- `Favour::{Blessed, Cursed}` (`Item.favour`, one or neither), `Known { magic, favour }` (`Item.known`, what has been found out). `Item::{can_be_magical, is_magical, roll_secrets, hide_secrets}`, `Inventory::hide_secrets`: see Notes. The rules for what they do are in `wear.rs` (`creature.md`).
- `Id(Uuid)`: something's id for good, for items, mobs, characters and accounts (the last two wrapped in `CharacterId` and `AccountId`). Prints as the usual UUID text, which also names files. `Id::for_test` is for tests in any crate. `Id::NOBODY` is nil, no real id.
- `ItemCategory::{ALL, name}` (Weapons, Armour, Clothing, Jewellery, Containers, Food, Valuables, Materials, Other: the owner's list), `ItemKind::category`: every kind in one, listed by hand with no catch-all, so a new kind needs one to build. For filtering and sorting grids.
- `ItemKind::{ALL, def()}`, `ItemDef { name, weight (grams), shape, container, wear, has_quality, make_percent }`, `WearDef` (see `creature.md`), `ContainerDef { width, height, max_total, max_each }`. To add a kind: add it to the enum, `ALL` (alphabetical by name) and `def`. Saved by name.
- `Shape`: up to `MAX_SHAPE_SIDE` (8) a side, as bits of a `u64`, gaps allowed. `rectangle`, `has`, `cells`, `size`, `turned`, `scaled` (for a `Size`), `smaller_than`.
- `Rotation::{None, Quarter, Half, ThreeQuarters}`: clockwise; `next`, `turn_cell`.
- `Quality::{ALL, odds, roll, magic_reach}` (Poor to Artifact, odds out of `ODDS_OUT_OF`), `Drop { quality, kind, weight }`, `roll_drop` (both rolls: quality, then the item at it; a table without that quality takes the nearest below, or else above).
- `Item { id, kind, contents, made, quality, made_at, name, set }` (`name()` is its own name or its kind's with its size unless `Medium`; every artifact has its own, from `artifact_name`, placeholders so far; `shape()` is its kind's at the size it was made: use it, not `def().shape`), `MadeAt { world, minute }` (each world has its own clock), `Made` (who it was made for: `for_body`), `Placed { item, x, y, rotation }` (`shape`, `cells`), `Holder::{Pockets, Inside(id)}`.
- `Inventory { creature, outfitted, pockets, pockets_size, worn, bin }`: `find`, `placed`, `grid`, `grid_size`, `total_weight`, `weight_with_creature`, `check_move`, `move_item`, `check_add`, `add`, `first_place_for_new` (the same for something not carried), `first_place_for` (a closed bag: the first place, turning if it must), `give` (a new item, first place in the pockets), `to_bin`, `to_bin_new`, `in_bin` (`bin` keeps what was last thrown away, and the next destroys it), `move_cost`, `put_down_cost` (what moves take, both sides), `sorted_grid`, `sort_grid` (a grid laid out again in one go: what looks the same stacked within the limits, then largest first by cells, then box, category, kind name and id, each in `first_room` from the top left keeping its turn unless it must turn; nothing changes if something wouldn't fit. Never ordered by an item's own name, which may hold secrets on the server, so both sides agree; it takes no time).
- `give_form(item, size, new_id)`: rolls a new item's form, for kinds with one (gems, rings), going by its quality and its id's seed, and sets its size to what it is told or what it rolled. Everything making items calls it. `Item.form` holds the result, `None` for other kinds and old saves. `Item::set_gems`. `ItemForm::{name, gems}` (`Hands(HandsForm)` for gauntlets, demi-gauntlets and padded gloves; `Shoulders(ShouldersForm)` for shoulder armour, whose form also gives its cells and weight; `Torso(TorsoForm)` for torso armour and arming vests, likewise, and whether it is lined; `Head(HeadForm)` for arming caps, coifs, helmets and bevored helms, likewise; `Arms(ArmsForm)` for arm armour, likewise, and whether it is padded; `Legs(LegsForm)` for leg armour, chausses and padded chausses, likewise; `Waist(WaistForm)` for waist armour and cuirassier tassets, likewise: see `armour.md`), `GemForm { material, cut, shape_seed }`, `Cut::{ALL, name}`, `RingForm { metal, profile, width, pattern, settings }`, `Setting { angle, size, mount, gem }` (`takes`), `Profile`, `BandWidth`, `Pattern`, `Mount`.
- `Limits { fits, at_least_long, most_grams, least_grams, wielder }`, `Limits::{NONE, allows}`: what a request needs of an item, so far only used by blades (`give_blade_within`, `give_commission`, which may change an item's kind). `ItemKind::blade_family`: `Axe`, `Dagger`, `Knife`, `Longsword`, `Polearm`, `ShortSword`, `Spear`, `Sword` are rolled as blades (see `blade.md`).
- `Material::{ALL, GEMS, name, category, tier, density}`, `Category::{Bone, Gem, Leather, Metal, Plant, Textile, Wood}`. Armour's materials (owner's decisions): Steel, Bronze, Brass, Mithril, Adamantine (Metal); Horn, Dragon Scale, Chitin (Bone); Leather, Hardened Leather, Buff Leather (Leather); Linen, Wool, Cotton, Silk (Textile); Rattan, Cork, Coir (Plant, nothing made of them yet). Rings roll only copper, gold, iron and silver, as before.
- `POCKETS` (6 × 4, for saves from before creature kinds and new inventories), `MAX_DEPTH` (3).

## Notes

- Everything carried is one tree starting from the pockets and what is worn: a worn bag's grid works as any other. `placed` is `None` for something worn. An item's id goes with it through any move.
- What may go in a container, in the order refused: not into itself; only a shape with fewer cells that fits within the container's **outside** (so a 2 × 2 pouch holding a 4 × 4 grid takes rings but not a stone, and each step in is smaller, which alone stops endless nesting); no more than `MAX_DEPTH` grids deep, counting grids inside what is moved; `max_each` and `max_total` for every container it would end up in, counting contents at every level; then room in the grid.
- A container it is already in gains no weight from a move within it. Weights are checked outward: a bag inside another counts with all it holds against the outer one's `max_each`.
- Nothing in the table is small enough to go inside a `SmallBox` and have a grid, so `MAX_DEPTH` is only reached by bags made by hand in tests, for now.
- Rolls are the server's: it is the only maker of items. A roll's odds and colours are first guesses; colours are the client's (`inventory`). Quality gives nothing yet. An item's quality may change, and its id doesn't. Design: `decisions.md`, 2026-11-02, item quality.
- Only what is worn, gems and blades come in sizes (`ItemKind::comes_in_sizes`); everything else is made `Medium`, whoever carries it or asks. Size changes only the outside of an item: each side is multiplied by `Size::quarters` (0.5 to 2), rounding down when enlarging and up when reducing, to at most 8. A blade's weight and cells come from its form, and its weight scales with its size cubed. A bag's grid, its limits and every other weight stay as they are, so a Tiny pouch is 1 × 1 and can hold nothing, and bags aren't rolled at other sizes yet. Saved items may now overlap: harmless, as they can still be moved apart, until the item wipe.
- A form is rolled once by the server and saved, never worked out again, as it will affect value: changing the rolls leaves existing items alone. The client only draws what it is sent. Each kind rolls its choices in order, each seeing those before: changing weights to lean on one (`Rng::pick_weighted`), or a weight of 0 to rule something out. Gems: quality, material, cut, size. Rings: quality, metal, band, number of settings, then each gem: first guesses for all of it. The finest gems never come Giant, by whole-number division.
- A gem set in a ring is a whole item with its own id, inside the ring's form, so taking one out later needs only moving it, and the setting stays. Rolled: about 5% of settings empty, 90% of gems after the first the same as it, 3% one size too big for the setting (owner's request, though they find it ugly), no uncut stones. A ring's quality is how it was made, and a gem has its own. `Inventory::find` doesn't look in settings, as nothing can move them yet: taking them out and putting them in is to come, by `Setting::takes`. Nothing but `holds_or_is` and weights needs to see them so far.
- Secrets: only what is worn can be magical (better than common) or blessed or cursed (any quality), rolled once by `roll_secrets` for shop stock and mob gear, 5% each as first guesses. They stay secret from clients until found out: `hide_secrets` is what the server sends through, so a client sees `magical: false` and no favour. Known is per item, for everyone from then on, not per character. `Item::name` says them ("Cursed Magical Hat", "The Band (Cursed, Magical)"), going by what its copy has, so it is for clients: the server's copy would give them away.
- Kinds are placeholders for trying this out, and the weights are guesses.
- Stacks (owner's design, 2026-11-03): items that look the same as the player knows them (`looks_like`: the `hide_secrets` copies, ignoring ids, `made_at`, the `Known` flags (what is known shows already) and what is stacked on them) share one place. The first in is the bottom, whose id is the stack's and stays while things are added and taken off the top; the rest are in `Item::above`, the top last (LIFO), each with nothing above it. The top is what shows, is named, is worn (`wear` takes only it) and comes off first; everything else (moving, dropping, giving, the bin) takes the whole stack. Comparing what is known means a refusal gives no secret away, and a stack with something known to differ (`is_even` false) takes no more. Bags never stack. Limits (`StackLimits`, the server's `HOW_STACK_GRAMS_PER_CELL`, 2000 g per cell of the shape, and `HOW_STACK_MAX`, 99, sent in `Welcome`; `NONE` stacks nothing): one item alone is always allowed. A bag's `max_total` counts the whole stack and its `max_each` one item of it. `give` stacks on the first stack it all fits on before finding room; dropping on a stack joins as much as fits, the rest staying where it was. Splitting: an id from inside a stack stands for it and everything above it (`part_of(stack, count)` names the top `count`). `lift_part` takes that part out on its own, lying exactly where its stack does, so any move (`move_item`, `stack_onto`, `wear`, the bin, handing over) takes it as it would anything; `settle_parts` puts back on its stack any part still lying there (the only way two things share a place: an item of the same kind exactly where another is), as when a move was refused. Mixed stacks: once something in a stack is known to differ (`is_even` false), `groups` sorts it by look, and `lift_group(stack, items)` lifts some of it out together, both parts keeping their order, the same way; one going back goes on top.
