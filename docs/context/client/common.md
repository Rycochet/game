# client: common

Shared building blocks for the client modules. Keep it small.

## Public API

- `Preferences` (resource): loaded at start, saved in `Last` whenever changed; a missing, old or unreadable file gives the defaults (`#[serde(default)]`), so add fields freely. `item_pictures`: Item Pictures' page name (`debug_menu`). `interface_size` (`InterfaceSize`: `Auto` or `Percent`) and `touch` ("Enable Touch"): set in Settings (`system_menu`), used by `widgets` for `UiScale`. `window` (`WindowPrefs`): how the window is shown (`display`, `last_full_screen` for Alt+Enter, `keep`), its windowed `place` (outer corner in physical pixels, inside in logical), `maximised` (true at first) and the `monitor`'s name.
- `Preferences::difficulty` (the player's own, set on Settings' Gameplay page before playing: sent in `Hello` and the creation screen's starting choice) and `server_difficulties` (Server Options' tickboxes: what the built-in server allows). `PlayDifficulty`, `difficulty_words`, `IRONMAN_QUESTION` (see `difficulty.rs` above).
- `Preferences::controls` (`Controls`): which keys do what (Settings, Controls). Every key the game reads for an action goes through it: `pressed`, `just_pressed`, `active` (either, for held steps), `clear_just_pressed`, `release` (lets go of all its keys, held too: the full map stills the camera keys), `is_key_of(action, key, held)` for code following key events, `uses_key`; `keys(action)` (two `Option<Binding>`s), `set(action, slot, binding)` (returns the places that lost it). `Action` (`StepUp`..`StepRight`, `Up` (Up / Leave, id `up`), `Down` (Down / Explore, id `down`), `CloseDoors` (Close Doors, L: `player`; until the FAB menu has a way), `TurnLeft`, `TurnRight`, `ZoomIn`, `ZoomOut`, `ResetView`, `NextTarget`, `PreviousTarget`, `Character` (C), `Inventory` (I), `Abilities` (B), `Skills` (K: `skills_page`), `UseSlot(slot)` (1 to 0: `abilities`), `FullMap`, `TurnItem`, `DebugMenu`, `FullScreen`; `ALL`, `name`, `id`, `group`, `defaults`: number pad keys always in the second column), `Group` (`Movement`, `Camera`, `Targeting`, `ActionBar`, `Interface`). `Binding { key, mods }`: a key with `Mods` (Ctrl, Alt, Shift, Super) held, or a modifier alone (`short_label`: at most three letters, `S1`, `^1`, `A1`, `W1`, `N1`, `F12`, for the action bar); left and right modifiers are the same (stored as the left); `new`, `can_bind`, `to_name`/`from_name` (`Shift+KeyG`), `label` ("Shift + G"; Super is Win or Cmd by system). Matching: a binding with modifiers needs them held; one without works whatever is held, unless another binding of the same key needing more of what is held matches. Saved as only the actions changed from their defaults, by name; unknown names are dropped, and a default some changed action now has is dropped from its old action. Esc, Backspace, text editing, list navigation, Shift-click and the creation screen's keys are not bindings.
- `DisplayInUse(DisplayChoice)` (resource): how the window is shown now (`DisplayMode` `Windowed`, `Borderless`, `FullScreen`, and full screen's `Resolution`, `None` for the screen's own); change it and `follow_display` changes the window, on the monitor it is on (`MonitorSelection::Entity` of `OnMonitor`; it waits for that at the start, so full screen opens where the window was). Set by `system_menu` (Graphics's Apply, Alt+Enter) and `dev_tools`. `RememberWindow(bool)` (resource, on): off while `dev_tools` set the window, so nothing about it is saved. `resolutions(modes)` (largest first, each at its fastest refresh), for the Graphics page; inside `common`, `closest_mode(modes, wanted)` picks full screen's video mode.

- `floors.rs`: `OtherLevels` (the site's other known levels, each a `CurrentDungeon`, for the maps: `entering`, `add`, `show`, `show_own`, `showing`, `shown`, `floors`, `spot`), `CurrentDungeon::floor_name` (for the full map's title; `describe` adds "of Y" for the HUD), `FirstFloor` (the first floor's number, 0 or 1, from the locale by `sys-locale`: the EU, UK and Latin America count from 0).
- `WorldChanged` (message): the player was moved to another world while playing; the maps forget their caches of the last one.
- `OwnAbility` (resource): when the player's ability began, lands and they can act again, by `Time` (`abilities` keeps it from `AbilityStarted`), and until when an ask waits for an answer; `is_busy(now)`.
- `CancelledEnergy` (message): what the player spent energy on was called off before it was done; `player` gives back all they still owe but for this much (`Energy::cancel`). `OwnAbility::is_winding_up(now)`: whether it can still be called off.
- `CurrentWorld` (resource): `id: WorldId`, `gates` (its World Gates, `GateInfo`s from `WorldInfo`), `params: WorldParams`, `surface: Surface`, `vegetation: Vegetation`, `celestial: Celestial`, `ground: WorldGround` (walking rules), `pois: KnownPois`, `roads: KnownRoads`; `CurrentWorld::water_level(clock)` (the tide from the world's own moons, kept apart from `celestial`, which debug tools may swap), `CurrentWorld::new(&WorldInfo)`. Only exists once the server has welcomed the client (inserted by `connection`, which also adds the chunks the server sends, marking it changed).
- `KnownRoads`: the roads the server has sent (`shared::road::Road`, by link), kept while in the world, not forgotten with the world map; `new(world_width)`, `insert`, `iter`, `steps()` (their `RoadSteps`, for step costs and routes), `changes()` (goes up with each, so drawings can tell they are out of date).
- `KnownPois`: the world map chunks the server has sent and their pois (`protocol::SeenPoi`, no map seed; `None`: known to have none). `insert(chunk, poi)`, `is_known(chunk)`, `in_area(min, max)` (as `PoiMap::in_area`: any planet-width frame). Unit test.
- `MapPosition { x: i64, y: i64 }` (component): position on the current view's grid; `y` increases southwards (towards the viewer). For the travelling player, the nearest grid point to `SmoothPosition`.
- `SmoothPosition { x: f64, y: f64 }` (component): exact position, fractional while the player travels, equal to `MapPosition` when still (`From<MapPosition>`). Anything with a `Token` needs one: `view3d` draws tokens there.
- `WorldReturn(MapPosition)` (resource): where the player stood on the world map before entering a site. Set by `site` (the way back out); `dungeon_map` reads it for the biome and weather outside.
- `ServerStatus` (resource): `Connecting` (the default; also while trying again after losing the connection), `Connected`, `Refused(reason)`; `is_connected()`. Set by `connection`; `player` only moves while connected, `loading_screen` shows it.
- `Hosting(OnlineState)` (resource, `hosting.rs`): how opening the built-in server to others went, set by `connection`, read by `system_menu`. `Preferences::online` and `online_settings`: Online and Server Options.
- `ChosenServer(Option<SavedServer>)` (resource): the server Connect chose, `None` for this computer's own (single player, or the page's); set by Connect, cleared by `connection` on going back to the startup menu (owner, 2026-11-10: Continue never goes back to another server). `HomeServer` (resource: `Checking`, `Found`, `Missing`): whether this computer's own server is there to play on: natively always, in a browser once the page's server answers `/_version` as a game server (`connection`). `SavedServer { address, key, name }`: a server joined before (as `ServerAddress` shows it), the fingerprint pasted in for it and the name it gave Connect's check; `label()` is the name, or the address if it has none or only `GAME_NAME`. `Preferences` keeps `servers` (latest first, at most 50): `joined` on each welcome from a chosen server, `forget_server` from Connect's bin. `client_file(name)` (native): a file beside the preferences (guest tokens).
- `Session` (resource): `AtStart` (the default: the startup menu, nothing connects) or `Playing` (Continue, Characters or Connect was pressed); `is_playing()`. Set by `system_menu` (those, Logout, a refusal) and `dev_tools` (`HOW_DEBUG_SKIP_MENU`); `connection` connects only while playing, and hangs up when it goes back to `AtStart`; `loading_screen` shows only the title then.
- `LoadingStep` (resource): `Starting`, `Connecting`, `Ready`; set by `loading_screen`, and `connection` waits out `Starting`. `frame_settings(keep_drawing, graphics)`: the `WinitSettings` (see Notes). `Preferences::graphics` (`GraphicsPrefs`): the Graphics settings trading looks for speed or clutter, each applied by the module drawing what it changes (frame rate here and in `loading_screen`, VSync here; Render Scale and Max Resolution (`MaxResolution` in `graphics/max_resolution.rs`; `drawn_share` combines them; the presets give 720p, 1080p and 1440p in a browser, and 1080p, Off, Off natively), Anti-aliasing and Reduce Motion in `view3d`; Shadows, Midday Sun, View Distance, Clouds, Foliage in `world_map`; Floor Textures and Remembered Places in `dungeon_map`; Brightness (`least_light`, below `BRIGHTNESS_MOST` 49%) and Weather (`Precipitation::share`) in both maps). What each can be is in `graphics/choices.rs`. `preset()` says which `Preset` they are, if any (worked out, never saved), `Preset::prefs` what each sets (Medium is the default, the game as it was) and `Preset::over` sets one keeping Brightness and Reduce Motion, the player's own. `Preferences::pause_unfocused`: "Pause When Not in Focus" (`system_menu` asks for the pause). `Preferences::quiet_slow_drawing`: the slow drawing warning's "Don't Warn Again" (`system_menu`). `IN_BROWSER`: for settings the browser decides, shown disabled. `KeepDrawing` (resource, off by default): keep the focused rate in the background; `dev_tools` turns it on, and `loading_screen` reapplies the settings when it changes. Natively the window opens as it was left (`window_open`), maximised the first time, which Auto interface size goes by. `remember_window` saves its place half a second after it stops moving; Bevy can only ask for maximised, so whether it is comes from winit (`WINIT_WINDOWS`, a thread-local, hence `NonSendMarker` to run on the main thread).
- `GameView` (Bevy state): `Connecting` (the default: waiting for the first welcome, no `CurrentWorld` yet; `connection` moves on to `WorldMap`; losing the connection later doesn't come back here), `WorldMap` or `Dungeon` (inside a site). Each view shows its scene and runs its systems only while current (`OnEnter`/`OnExit`, `in_state`). Switched by `site`.
- `HerbGrowthShift` (resource): stages added to how far herbs have grown, for the debug menu and dev tools.
- `CurrentDungeon` (resource): the site level as far as the server has told: `info: Option<LevelInfo>` (kind, floor/level, bounds...), `level` (`shared::dungeon::Level`: unknown cells are wall), `buildings` (a town's: `add_buildings` marks their cells on `level`; `door_facing(x, y)`, `is_town()`, `knows_outside()`), `fields` (a farm's, set by `site`), `known` (cells sent), `remembered` (cells seen now or before, drawn in grey when out of sight; includes what is in sight), `stairs: Vec<SeenStairs>` (known stairs, with the way they go down), `in_poi` (in the wilderness, the kind of poi set in that the player stands in, from `InPoi`), `borders` (in the wilderness, the cells round known pois' cutouts, from `Borders`: hatched by `dungeon_map`, a click leaves by `site`; `describe()` then gives "Wilderness: RockCave"), `flats` (in the wilderness, the groups of pois' covered cells kept level, from `FlatGround`, each kept once by `add_flats`; only cells not out in the open in them are levelled). `enter(info)`, `add(&LevelChunk)` (cells, stairs, and doors' swings set on `level`; a door seen open or without a lock is no longer known locked), `door_locks` (doors seen to have a lock), `move_window(bounds)` (the wilderness's level moved: what is known where old and new overlap stays), `is_wilderness()`, `describe()` for the HUD ("Castle, floor 2 of 3"; "Hall of Worlds" there, `info.kind` being `LevelKind::Hall`). Changed by `site`; read by `player` (walkable cells) and `dungeon_map` (which adds to `remembered` without marking it changed).
- `PointerPosition(Option<Vec2>)` (resource): where the player is pointing: the finger, otherwise the mouse. Read this rather than `Window::cursor_position`. `TouchGesture` (resource): this frame's `drag`, `drag_start`, `pinch`, `twist`, `tilt`, `centre`; `minimap` takes it while the full map is open. `PointerSystems` (system set, `PreUpdate`): where they are written. All by `touch`. These are in logical window pixels, for the maps and the 3D views.
- `UiPointer(Option<Vec2>)` (resource): the same point in the interface's own pixels, which `UiScale` makes bigger or smaller: what `Node`s are placed and sized in, so every hit test and anything placed at the pointer uses it. `in_interface(at, scale)`, `interface_area(window, scale)`: a point or distance in window pixels, and the window's size, in interface pixels (convert `TouchGesture`'s positions and drags with it). Never mix the two: they agree only at 100%.
- `ClickMode` (resource): `Normal`, `Teleport`, `ChangeCell`, `PlaceMob` (Mob Mode), what a click on the map does; `CreateMobOrder(DevMob)` (resource, `debug.rs`): the mob Mob Mode puts on a cell, edited by `debug_menu`'s Create Mob, sent by `dungeon_map`; `FreezeMobs` (resource: a dev tools switch, set by `debug_menu`, read by `ui`); `InspectedMob { mob, lines }` (resource: the server's last answer on a mob, for Examine Mob's panel and `client.inspected`); set by `debug_menu`, read by `world_map`, `dungeon_map`, `minimap`, `ui`. `DebugInfo(bool)` (resource): whether `ui`'s status text shows the hour and view stats (Show Debug Info; on by default). `TeleportToWorldAsked { seed }` (message, `debug.rs`): open the debug menu's Teleport to World with that world's seed; sent by `planet_view`, read by `debug_menu`. `CurrentDungeon::level_has(cell)`.
- `DebugTools` (resource, `debug.rs`: a bit per `role::DebugTool`, so `Copy`; `of`, `every`, `may(tool)`, `any`): the debug tools this player may use, set by `connection` from `Welcome`; read by `debug_menu` (entries and panel buttons hidden without theirs, no menu without any), `planet_view` (Teleport to World), `ui` (Show Debug Info; the status box moves left without the warning button) and `system_menu` (no Debug Menu row in Controls without any). `KnownPois::forget_all`.
- `StockCell`, `HeldStock`, `TookItem`: picking up what someone has to trade.
- `HoveredBag` (resource): the cell of the bag on the ground the pointer is on; `ground` sets it, `dungeon_map` leaves such clicks alone, `hover` names it.
- `Target` (resource): the creature the player has targeted, by id; set by `target`, kept while out of sight.
- For `hover`'s box: `HoverName` (component: what a token is called; a token with one can be hovered though not clicked: `entities` puts it on others), `AccountRole` (resource: the account's role and powers, kept by `accounts_panel`; `has_accounts_panel`), `OpenAccounts` (message: the system menu's Accounts), `StaffMark` (component: another player shown as a marked role, by the role's name: `entities` puts it on, `hover` shows the mark and the name), `HoveredOnMap` (resource: the door or stairs under the pointer, from `dungeon_map`), `HoveredInSky` (resource: the sun or moon by the minimap, from `minimap`). `poi_name(poi)` and `words("StoneTower")` ("Stone tower") name things written in code style.
- `GROUND`: who `StockCell` and `TakesGifts` say for the ground under the player. `SpentEnergy` (message): the player did something that takes energy; read by `player`. `Dressing` (message): how much of that was putting on or taking off, from `inventory`, shown by `entities` (a placeholder for a progress widget).
- `TakesGifts`, `HeldOverGifts`, `HeldGift`, `GaveItem`: dropping a held item on something to give it to someone, between `inventory` and `trade`.
- `BandShift`: how far the bands on set items' edges have slid, from `view3d` for `widgets`.
- `quality_colour`, `NO_QUALITY_NAME`: how an item's quality is shown, for `inventory` and `widgets`.
- `Portal` (component): `Poi(SeenPoi)` or `Gate(GateInfo)`: clicking it sends the player there and arriving enters its site, or goes through the World Gate into the Hall (`site`); `poi()`. World map pois and World Gates have one; stairs and the Hall's gates are cells of the level, not entities.
- `Token::no_base`: draws no base, for a world map poi's model; still clickable.
- `Clickable` (component, marker): its token can be clicked (`view3d::ClickedToken`).
- `LightSource` (component): `radius` (cells) and `colour`; lights dungeons. The player has one (6 cells, white).
- `SharesSight` (component, marker): its sight is added to the player's in dungeons. Nothing has it yet.
- `Lightning(f32)` (resource, `lightning.rs`): how bright lightning makes what is under the sky this frame, 0 to 1; kept by `lightning`, changing only during a flash. `LightningStrike` (message): start a flash now (the debug menu's Lightning Now; `lightning` reads it). `BoltStruck(Strike)` (message, from `lightning`): a bolt strikes here, in wilderness cells, for the views to draw.
- `SkyNow` (resource, every frame): `bodies` (`shared::celestial::BodyNow`s), `flat` (their light on flat ground), `lit()` (what to multiply unlit colours by). `NIGHT_LIGHT`: the dull light everywhere, 0.1.
- `ServerClock` (resource): `minutes` (float, running unless paused: game minutes since the world began, `hours()` for what goes by hours, as near the server's as `connection` can keep it; changes every frame), worked out from `seconds` (the server's clock) and `time` (the world's `WorldTime`) by `set(seconds, time)`, `round_trip_ms`, `paused` (the server's clock has stopped, and `Time` with it), `can_pause` (the server would stop it if asked).
- `GameClock` (resource): `hour` counting up for ever (`% 24` is the time of day; tides use it as is), set by `connection` from the server's `Welcome` and `Hour`; only changes on the hour (use `is_changed()`).
- `ViewStats` (resource): `summary` line written by the current view, shown by `ui` (so `ui` needn't depend on the map).
- `Token` (component): `shape: TokenShape` (`Circle`, `Triangle`, `Square`, `Hexagon`, `Octagon`) and `attitude: Attitude` (`None` white, `Friendly` green, `Neutral` blue, `Unfriendly` red; `Attitude::colour()`), and `completed: bool` (secondary state: drawn ~30% darker and slightly see-through), and `size: TokenSize` (how big its `Icon` is drawn; the base never changes: `Tiny` 0.5, `Small` 0.75, `Default` 1, `Large` 1.25, `Giant` 1.5, `Titan` 2; `scale()`). World map pois are `Tiny`, the player `Default`. How an entity is shown on maps; set by its owning module (`player`), drawn by `view3d`. The enums have `ALL` and `next()`.
- `Icon(String)` (component): a 2D picture shown above an entity's token, standing upright and turned to face the camera; asset path such as `monsters/humanarcher.png` (54×54 art, main picture in the central 32×32). Set by the owning module, drawn by `view3d`.
- `IconPicture(Handle<Image>)` (component): a drawn picture shown in place of the `Icon` (a character as dressed, from `item_art`), filling its whole square, so drawn at the icon art's central size. `entities` sets it.
- `PadButton` (component) and `PadSteps` (resource, `step_pad.rs`): the movement pad's buttons (Up, the four step arrows, Down), and the steps its held arrows ask for, as screen `dx` / `dy`. `step_pad` spawns the buttons and writes `PadSteps`; `player` steps by it, `site` enables Up and Down.
- `ViewFacing(u8)` (resource): which compass direction is nearest the top of the screen, in quarter turns clockwise from north (0 north, 1 east, 2 south, 3 west). Written by `view3d` from its camera; `screen_to_grid(dx, dy)` turns a screen direction into a grid step (used by `player` for keys).
- `CurrentWorld::conditions(clock)`: the walking rules now (the hour's tide; frozen sea counts as ground, by the climate), for `player` and `world_map`.

## Notes

- The camera belongs to `view3d`, not here.
- `MapPosition` is the position in the current view's grid; the world map and dungeon grids are unrelated (`site` keeps the world map position while inside a site).
- Frame rate: `WinitSettings` reactive mode at the chosen Frame Rate Limit (30 by default; Unlimited is continuous) while focused and 1 fps unfocused (except while loading, with `Background::KeepDrawing` chosen, or with `KeepDrawing`, which the debug API and screenshots turn on); input wakes it immediately. Not a twitch game, so the low default saves GPU and power.
