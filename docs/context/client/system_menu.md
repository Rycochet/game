# client: system_menu

The system menu: Esc or the gear button top right (the way in on touch devices) opens a small panel in three sections: Continue (and Characters at the startup menu), Online (with Server Options' gear on this game's own server; on another, only for staff who may lock it down) and Connect...; Settings and Credits; Logout and Quit. While it is open, single player is paused. The same menu is the startup menu over the title, until Continue, Characters or Connect starts playing (`common::Session`). Accounts moved to the debug menu's Admin Tools (owner, 2026-11-10). Native and web.

Unit tests. Beside it: `state.rs` (`SystemMenu`, `Action`, `MenuButton`), `spawn.rs` (gear, layers, requester, Settings, `spawn_title_row`), `panel.rs` (the menu's sections, `SECTIONS`), `input.rs`, `show.rs`.
- `crates/client/src/system_menu/connect.rs`: Connect (startup menu only): example, address box (`AddressBox`), padlock (`PadlockButton`, native only), the remembered servers (`ServerList`, rows by `spawn_server_row` with a bin), Connect and Cancel. In `connect/`: `form.rs` (`ConnectForm`: a key pasted or cleared and the address it is for, the server being forgotten; `open_connect` fills the box with `ChosenServer` or the latest server, or else `SUGGESTED_SERVER` (`hallofworlds.app`, the game's public server, not remembered until joined), and after a refusal keeps the key tried; `fill_server_list`; `use_connect`, Connect's presses, which `SystemMenu::after` leaves to it), `show.rs` (`show_connect`: Connect and the padlock only for an address, the padlock shut while a key is kept, Keep only for a certificate), `popups.rs` (the certificate box and the forget requester, whose yes also sends `LoginChoice::ForgetServer`, forgetting any login kept for it), `check.rs` (`AddressCheck`, `check_address`: 0.6 s after typing stops, or at once when the box was filled another way (opening, picking a server), asks `connection::ServerProbe` for the ports `ServerAddress::ports_to_try` gives (the one typed, or 24691 then 443), again whenever the text or the key kept for it changes; `Checked::{Waiting, Checking, Found, Failed(reason)}`; a server of another protocol is a failure; the box's grey `suffix` is the port found when none was typed; `ready_for(text)` is what Connect connects to), `mark.rs` (`spawn_mark` in the buttons' row, just left of Connect (owner, 2026-11-10: it didn't show inside the box); `show_mark`: spinner while checking, tick (tooltip: the server's version) or cross (the reason)). Connect is only enabled while `ready_for` the box's text, and joins the address with the port that answered, always written (owner), for `PlayFor::Choose`: Character Select, or a guest straight in (`connection`). `open_connect` fills the box with the server that just refused (`refusal::TriedServer`, with its key), else the latest joined, else `SUGGESTED_SERVER`. `icons.rs`: padlock shut and open, bin, tick, cross.
- `crates/client/src/system_menu/online.rs`: the Online row (`spawn_online_row`: a check button, ticked while on (owner, 2026-11-07), with the gear attached, `OnlineGear`), `use_online` (at once, or the Go online / Go offline requester while playing on the built-in server; on another computer's server the Lock down / Open to everyone requester (`SystemMenu::LockingDown`, `Reopening`), whose yes sends `SetLockdown`), `show_online` (ticked for `Preferences::online`, or on another server while `common::Lockdown` is `Some(false)`; the gear only for this game's own server, natively), `show_online_failure` (`Hosting` failed: Online off again, and the reason). Native and web (owner, 2026-11-10): `show_buttons` shows Online at a native startup menu, while playing on the built-in server, and on another only while `Lockdown` is told (staff with `Permission::ServerOptions` on a networked server); never at a browser's startup menu.
- `crates/client/src/system_menu/server_options.rs` (native): Server Options: name, public address, listen address, port, player limit, the difficulties' tickboxes (`server_options/difficulty_row.rs`: `run_difficulty_boxes` keeps them in `Preferences::server_difficulties` at once, the last ticked disabled (`box_state`); `HOW_DIFFICULTIES`, read once, shows them all disabled with a tip), the router's switch and line (`server_options/upnp_row.rs`: `UpnpSwitch`, kept on closing like the boxes, unless `server::upnp_from_environment` (`HOW_UPNP`) decides, when it shows that, disabled, with a tip, and `in_use` applies it to what the line says; `router_words` from `Hosting`'s `RouterPort`, in `WARNING_TEXT` for a refusal or a shared address; Copy, `Action::CopyRouterAddress`, only shown with an address to copy; `run_upnp_rows` after `run_server_options`) (`OptionBox`: filled on opening, wrong ones marked, the right ones kept in `Preferences::online_settings` on closing, which reopens the server if online), and the certificate (the one in use, or `tls/certificate.pem` in the data folder) with a clipboard button beside its label (`widgets::spawn_copy_button`). Tests.
- `crates/client/src/system_menu/requesters.rs`: the simple requesters as markup (`dom`), one template: Quit (`quit`), Ironman (`ironman`), Keep these settings (`settings.keep_graphics`), Can't connect (`refused`) and Slow drawing (`slow_drawing`), each a `<dialog id="requester">` in a form of that name. `spawn_requesters` builds them and fills the words kept in code; `bind_requesters` gives each new dialog its `Layer` and each button its `Action` (and Keep its `KeepButton`), found by id, so `show_menu`, `take_input` and `run_trial` work on them as on any other. Words that change are set by id (`refused/words`, `settings.keep_graphics/countdown`). Unit tests.
- `crates/client/src/system_menu/refusal.rs`: `show_refusal`: a refusal while playing (being sent away too, such as for idling) goes to `Session::AtStart` and the "Can't connect" requester with the reason in red, keeping the server chosen in Connect as `TriedServer` (as `connection` forgets `ChosenServer`); its OK goes to Connect if there was one, else the menu.
- `crates/client/src/system_menu/slow_drawing.rs`: `warn_of_slow_drawing`: once a run, at the startup menu, the "Slow drawing" requester (`SystemMenu::SlowDrawing`) when `is_slow` finds the game drawn without a graphics card: Bevy's `RenderAdapterInfo` of type `Cpu` or named as software (SwiftShader, llvmpipe, softpipe, Microsoft Basic Render), or in a browser `index.html`'s `window.howSlowDrawing` (WebGL refused with `failIfMajorPerformanceCaveat` but given without). Play Anyway (`Action::Back`) and Don't Warn Again (`Action::QuietSlowDrawing`, sets `Preferences::quiet_slow_drawing`). Words differ in a browser. Natively `WGPU_FORCE_FALLBACK_ADAPTER=1` shows it (Windows' software renderer). Unit tests.
- `crates/client/src/system_menu/credits.rs`: the Credits layer (`CREDITS`: what was done and by whom), a scroll area that `start_credits` restarts from the top with `widgets::AutoScroll` each time it opens. Test: every bold label on `docs/credits.md` is in it.
- `crates/client/src/system_menu/full_screen_key.rs` (native): Full Screen's keys (`common::Action::FullScreen`, Alt+Enter at first) between windowed and `WindowPrefs::last_full_screen`, at once and saved; in `PreUpdate` before the widgets, following the modifiers by their own `KeyboardInput`s, as the open menu lets go of every held key (and forgetting it on `KeyboardFocusLost`). Not while a text box has the keyboard, or `KeepGraphics` is up.
- `crates/client/src/system_menu/settings.rs`: Settings' tabs and pages (`spawn_pages`; hidden pages take no room): Gameplay (`settings/gameplay.rs`; Shown As in `settings/shown_role.rs`: `ShownAs` kept from `Welcome` and `RoleAnswer::Shown` / `Changed`, a dropdown only while playing with more than one choice, sending `RoleAsk::ShowAs`), Controls (`settings/controls.rs`), Interface and Graphics (`settings/graphics.rs`). `settings/rows.rs`: what pages are made of: `spawn_sections(page, key, fill)` (one under another, each the page's whole width, scrolling in what is left of the page and keeping its place by `widgets::ScrollKey` when the page is rebuilt or Settings opened again; pages fill the rest of the panel), `spawn_section` (a heading and rows), `spawn_labelled` / `spawn_dropdown_row` / `spawn_switch_row` (a label and a control with a `widgets::HoverTip` over the whole row), `tip(what, why_not)` (a setting's words, and why it is disabled). `settings/gameplay.rs`: Difficulty, Shown As (staff only), then "Pause When Not in Focus" (`Preferences::pause_unfocused`), a switch, disabled in a browser and while playing on another computer's server, with the reason in its tip; rebuilt when either changes, on every `PlayDifficulty` change and as the Ironman requester opens and closes. `settings/difficulty.rs`: `choices` (with no character, all four as the player's own, `Preferences::difficulty`; with one, the server's allowed ones it may change to, never to or from Ironman, disabled with a reason when there are fewer than two), `spawn_difficulty_row`, `use_difficulty` (while playing, `SetDifficulty`; otherwise into `Preferences`, Ironman only after `SystemMenu::Ironman`'s yes, `Action::ChooseIronman`). Interface has the Interface Size dropdown (Auto, then `widgets::INTERFACE_PERCENTS`) the "Enable Touch" switch (on and disabled on a touch-only device, `widgets::TouchOnly`) and the "Always Show Scroll Bars" switch (`Preferences::always_show_scroll_bars`, id `settings.interface/scroll_bars`), as labelled rows with tips. `fill_interface_page` rebuilds it when `Preferences` change; `use_pages` switches pages and writes the choices into `Preferences`. - `crates/client/src/system_menu/settings/controls.rs`: the Controls page (no Debug Menu row without any `common::DebugTools`): a section per `common::controls::Group`, rows of the action's name (taking what is left) and two `widgets::KeyBox`es of fixed width (owner: a table, every other row `ROW_TINT`, no header, no tip on the rows), then Esc's row ("Menu / Back", both boxes disabled, with a tip saying why), then Reset to Defaults. `ControlBox(action, slot)`; `use_controls_page` puts `KeyChosen` into `Preferences::controls` (`Controls::set`), and the places that lost the binding go in `TakenKeys` (shown with the error edge and "M is now used by Step Up." as the box's tip) until Settings closes (`forget_taken`); `fill_controls_page` rebuilds only when the bindings or `TakenKeys` change. ## Notes

- Ids (`widgets::UiId`): buttons by their `Action` (`Action::ui_id(form)` in `state.rs`: `menu/settings`, `quit/quit`, `connect/server.2`), big layers' close buttons `<form>/close` (`spawn_title_row`), Settings' tabs `settings/page`, Graphics's rows by `GraphicsControl` (`settings.graphics/frame_rate`), Server Options' boxes by `OptionBox`. The two Online requesters are `going_online` and `going_offline`; the Ironman requester's buttons `ironman/ironman` and `ironman/no`; Gameplay's dropdown `settings.gameplay/difficulty`; Server Options' tickboxes `server_options/difficulty.<0-3>` (Easy to Ironman).

- Startup menu: while `Session::AtStart` the menu is always open, and Esc and outside presses do nothing. Continue (`Action::Continue`, `PlayFor::Latest`: straight into the character played last, so only enabled when this computer has one there) and Characters (`PlayFor::Choose`: Character Select) set `Playing` and close it, always for this computer's own server (owner, 2026-11-10: no going back to the last server joined); both are hidden until `HomeServer::Found` (a browser asks its page's server first). While playing, Continue only closes the menu. Logout (shown while playing on a server that isn't built in: always on the web) sets `AtStart` and keeps the menu open, and `connection` hangs up. At the startup menu it shows only while an account is kept for this computer's own server (`common::AccountEmail`: a browser's page's server), and sends `LoginChoice::LogOut`: `connection` forgets that account. Credits are kept by hand beside `docs/credits.md` (the owner's name is only in the game's).
- Owner's design: no close button or title on the menu; "Paused" above the first button, taking no room while not paused (`Display::None`), so the menu is shorter in multiplayer. Quit asks "Are you sure?" in a small requester, whose "No" closes only that. Settings is a layer 50% of the window wide and 75% high, with tabs (owner's choice).
- Claude's choices: Esc or a press outside closes what is on top, one layer at a time (touch has no Esc, and the menu no close button). Settings closes back to the menu. The gear sits in the corner outside the round minimap, so a low sun or moon can pass behind it, and is hidden while connecting, as the warning button is.
- Esc: text boxes and dropdowns use it first (`Presses`). `take_input` runs before the debug menu and full map, leaving it to them if they are open. While open, the menu takes all keys, the wheel, gestures and right button, so backtick and M do nothing.
- Pausing: `ask_for_pause` sends `SetPaused` as the menu opens and closes, and as the window goes into the background and comes back with "Pause When Not in Focus" on, if the server said it can (`ServerClock::can_pause`). Only the server's answer stops anything (`connection`, see there), and "Paused" shows only then. In multiplayer nothing pauses: keys are blocked, but click travel carries on.
- Quit: `AppExit`, which `connection` hangs up on. In a browser `show_ended_page` also shows the `#ended` screen in `index.html`, a copy of the loading screen with a "Click to reload" button, over the stopped canvas. Its colours and sizes are shared with `#loading` there.
