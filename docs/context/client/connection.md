# client: connection

The client's connection to the server: joining, sending the player's steps and putting right the ones the server refused, storing world map chunks, and passing messages between other modules and the server. Native clients start the embedded single-player server (`server::start_embedded`) and talk to it through an in-process `Link`, or connect to a server named by `HOW_SERVER` (`wss://...`, or plain `ws://...`); the web client connects over a WebSocket to the server it was loaded from. A lost connection is tried again every 2 s, unless the certificate fails its checks or the server says to use TLS; `common::ServerStatus` says how it is going (`loading_screen` shows it). On quitting it hangs up and waits for the embedded server to save.

## Files

- `crates/client/src/connection/mod.rs`: `ConnectionPlugin`; `connect` (PreUpdate, exclusive, while there is no `ServerConnection`, the server hasn't refused and `common::LoadingStep` is past `Starting`: every `RETRY_EVERY` (2 s), opens the private `Connecting::target` (embedded, or a WebSocket), says `Hello` straight away (the link holds it until the socket opens) and starts a fresh `Prediction`), `receive` (PreUpdate, after `connect`: `LoginOptions` is answered by `log_in` with the guest token, and with no guest method, or on `Characters`, as there is no menu yet, `give_up` hangs up and sets `ServerStatus::Refused`; `Welcome` sets `ServerStatus::Connected` and makes `common::CurrentWorld` (added after the loop, so the chunks that follow in the same batch go into it), puts the player where the server says and moves to `GameView::WorldMap` (if not there already), after checking `WORLD_MAP_VERSION`, and is passed on to `site`; `Refused` sets `ServerStatus::Refused` with the words to show (no more tries), as does the socket's `Refusal`; a lost connection removes `ServerConnection` (and the browser socket) and sets `ServerStatus::Connecting`; `WorldChunk` goes into `CurrentWorld::pois`; `Position` goes through the `Prediction`, and moves the player if the result differs from where they are shown; `EnterLevel`, `LevelCells`, `OnWorldMap` and `Teleported` are passed on as `FromServer`; ), `send_steps` (Update after `PlayerSystems::Travel`: each `player::Stepped` becomes a `Step` message), `count_map_changes` (PostUpdate: `EnterLevel`, `OnWorldMap` and `Teleported` start a new map for steps), `send` (`Last`): sends every `ToServer` written this frame, in order. `hang_up_on_exit` (`Last`, after `send`): on `AppExit`, removes `ServerConnection`.
- `crates/client/src/connection/socket.rs`: `Target::{Embedded, Url}` and `choose()` (native: `HOW_SERVER` or embedded; web: `ws(s)://<the page's host>/ws`), `open(url)` (native: a "socket" thread running `tungstenite`, `wss://` through `trust` or plain `ws://`, polling reads every 2 ms between sends, also sending pings), `Refusal` (native: why the socket gave up for good), `BrowserSocket` (web: the browser `WebSocket`, binary messages as `ArrayBuffer`s so they stay in order; incoming go straight to the link, `pump()` sends outgoing and pings once open; dropping it closes it).
- `crates/client/src/connection/guest.rs`: `token(target)`: the guest token for this server, made when first needed and failing rather than using weak randomness. Web: local storage, `hall-of-worlds-guest-token`. Native: `guest_tokens.ron` beside the known servers, by `host:port`, with `HOW_DEBUG_GUEST` naming a slot for several clients on one computer; an unreadable file is left alone and that run is a new guest. Tests: keys, tokens kept per server, unreadable file untouched.
- `crates/client/src/connection/trust.rs` (native only): `connector` (TLS settings for one `host:port`), `ServerTrust` (the checks: `HOW_SERVER_KEY`'s fingerprint if set; else a certificate authority through `rustls-platform-verifier`; else the public key must match the one remembered, or is remembered on a first visit; dates always), `KnownServers` (`host:port` → `Authority` or `Key(fingerprint)`, in `HOW_KNOWN_SERVERS` or `Hall of Worlds/client/known_servers.ron` in the user's data folder; an unreadable file refuses rather than forgets). Tests: each case, with a stand-in authority.
- `crates/client/src/connection/prediction.rs`: `Prediction` (resource: map count, last step number, steps not yet confirmed; `step`, `changed_map`, `confirmed(map, step, at) -> Option<predicted>`), `correction(shown, predicted, width)` (where to move the player, if anywhere; on the world map the same place on another copy of the planet counts, and a move stays on the player's copy). Tests: confirmed steps forgotten and later ones added, a refused step moves the player back, positions from a left map ignored, the world map wraps.

- `crates/client/src/connection/ping.rs`: `PING_EVERY` (1 s), `Pinger` (makes `Ping`s, spots and times `Pong`s in incoming bytes), `LatestPong` (where the game picks up the newest `TimedPong`; older ones are dropped). Tests: timed, other messages left alone, only the latest kept.

Also keeps `common::ServerClock`: `run_clock` runs it in real time, and `apply_pong` (after it) eases it towards the server's clock plus half the round trip and however long the answer waited for this frame (jumping if over 5 s out). Over a network, the socket sends the pings and times them, so slow or frozen frames don't count and it carries on while the window is frozen; the game only sees the result. Single player has no socket: `send_local_pings` sends them once in a world, and `ServerClock::local_server` makes the HUD show a dash as there is no network to time.

## Public API

- `ToServer(ClientMessage)` (message): send this to the server (at the end of the frame).
- `FromServer(ServerMessage)` (message): a map message from the server (`Welcome`, `EnterLevel`, `LevelCells`, `OnWorldMap`, `Teleported`), read by `site`.
- `ServerConnection` (resource): the link to the server, and the embedded server (native); removed while disconnected and on quitting.

## Depends on

- `common` (`CurrentWorld`, `GameView`, `MapPosition`), `player` (`Player`, `PlayerSystems`, `Stepped`), `shared::movement`, `shared::protocol`, `shared::world`; `common::ServerStatus`; native only: `server` (`start_embedded`, `EmbeddedServer`, `DEFAULT_WORLD_SEED`, `default_data_folder`, `certificate_facts`), `tungstenite`, `rustls`, `rustls-platform-verifier`, `ron`, `serde`, `dirs`; web only: `web-sys`, `js-sys`, `wasm-bindgen`.

## Used by

- `site` (`ToServer`, `FromServer`), `dev_tools`, `debug_menu`, `world_map` and `dungeon_map` (`ToServer`: dev tools messages); other modules see `CurrentWorld` and `GameView`.

## Notes

- `receive` runs in `PreUpdate`, so the state changes on the same frame `Welcome` arrives, and `OnEnter(GameView::WorldMap)` already finds `CurrentWorld`. `dev_tools` starting positions apply after it (on leaving `Connecting`), so they win over the saved one.
- `ServerConnection`'s fields are dropped in order: the link first (the server sees its client leave, saves and stops), then the `EmbeddedServer`, whose drop waits for that. Swapping them would hang on quitting.
- Map changes are counted in `PostUpdate`, after `site` has applied them: steps taken earlier in that frame were still on the last map. Steps sent just before a map change are never confirmed; the server ignores them.
- Corrections cancel travel (any direct change to `MapPosition` does, `player`). A journey stops where the server refused a step (memory can be out of date).
- Reconnecting keeps the view on show: `Welcome` replaces `CurrentWorld` (poi tokens respawn), the player is put where the server says, and `EnterLevel` follows if they are in a site. Movement waits for `ServerStatus::Connected`.
- `dev_tools` start-up states run on leaving `GameView::Connecting`, which only happens on the first welcome.
- Browsers check `wss://` certificates themselves: the checks in `trust` are native only. A first visit to a self-signed server can't be told from an attacker's, which `HOW_SERVER_KEY` (compare with the fingerprint in the server's log, or its `/certificate`) closes. There is no prompt yet, as there is no server picker.
